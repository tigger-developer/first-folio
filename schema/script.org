* Scope

This is First Folio's Org source format for *stage plays and screenplays*.
Both use the same document structure. British stage-play, US stage-play, and
screenplay styles control the rendered layout, not the source schema.

- Play example :: [[file:../examples/play-example.org][One Day]].
- Screenplay example :: [[file:../examples/cold-open.org][Cold Open]].
- Combined play and letters :: [[file:../examples/about-time.org][About Time]].

* Frontmatter

Place keyword lines at the beginning of the document, starting at column one:

#+begin_src org
#+SCHEMA: https://github.com/tigger-developer/first-folio/blob/master/schema/script.org
#+TITLE: A Short Play
#+SUBTITLE: A Play in One Act
#+AUTHOR: A. Playwright
#+DATE: 2026-09-10
#+VERSION: Draft 1
#+end_src

- =SCHEMA= :: Identifies this source format. Org conversion output always adds
  this value, even when the input has no schema declaration.
- =TITLE=, =SUBTITLE=, =AUTHOR=, =DATE=, =VERSION= :: Document metadata retained
  by the Org writer when present.
- Other keywords :: May be captured on input, but preservation through text
  conversion is not guaranteed.

The output declaration describes the destination. Converting to Markdown
changes it to the [[file:script.md][Markdown script schema]]. Schema declarations
are not added to Fountain, Typst, or PDF output.

* Play structure

Heading levels have fixed meanings. A heading starts at column one with the
indicated number of stars followed by a space.

| Source form | Meaning |
|-------------+---------|
| =* Act I= | Act or other major play division |
| =** Scene 1= | Scene within an act |
| =*** A kitchen. Morning.= | Stage direction or screenplay action |
| =**** ALEX= | Speaker cue |
| Plain lines after a speaker cue | Dialogue |
| =*** BLACKOUT :transition:= | Transition |
| =*** KEEP OUT :prop:= | Text displayed within the play |

Speaker names may contain Unicode characters. Use uppercase names to distinguish
names from attached directions: =**** ALEX softly=, =**** ALEX (softly)=,
and =**** ALEX, softly= identify the same speaker and direction. Multiple
dialogue lines are retained; empty lines are not separate dramatic events.

A level-five heading is also accepted as a historical transition form. The
writer uses the level-three =:transition:= form.

** Cast table

A level-one =CHARACTERS= or =CHARACTER= heading introduces a two-column cast
table. The heading match is case-insensitive. Each data row contains a name
and description; separator rows are ignored.

#+begin_src org
| ALEX | A visitor |
| CÁIT | The host  |
#+end_src

** Introductory material

Major sections before the first act containing a speaker cue are introductory
material, for example Synopsis or Setting. The =render.frontmatter=
configuration setting controls their inclusion in rendered output.

** Footnotes and inline text

An inline =[fn:note]= refers to a definition of the form
=[fn:note] Explanation.= on its own line. Definitions are emitted after the
play body.

Org inline markup is interpreted by the Org-aware PDF renderer. Text conversion
does not translate every inline marker into the destination syntax; equivalent
inline appearance across Org, Markdown, and Fountain is not guaranteed.

The historical prop form =- *"KEEP OUT"*= is accepted. Org output uses the
=:prop:= heading form shown above.

* Excluded sections and letters

A heading tagged =:noexport:= excludes its whole subtree. Ordinary play content
resumes at the next heading of the same or a higher level.

An Org script may also contain *both the play and cover letters*. Such a file
keeps the script schema in its document frontmatter. Its level-one =:letter:=
sections follow the separate [[file:letter.org][Org letter schema]].

The required command boundary is:

- =folio convert= converts the play and *excludes letter subtrees*.
- =folio letter= generates *only recipient letters* from the same source.

Letter exclusion during play conversion is a known outstanding defect recorded
as [[file:../docs/work.org::#w-040][W040 - Exclude cover-letter sections from document rendering]].
The schema declares the required boundary; the schema-field change does not
itself resolve that defect.
