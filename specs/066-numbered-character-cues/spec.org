** Outcome
- Org script exports *retain numeral components in character names*.
** Before
- =**** PARENT 3= *split the 3 into a direction* and malformed the output cue.
** After
- =PARENT 3= and other numbered names *render as complete cues*; a following parenthetical remains a direction.
** Changes
- The shared Org speaker parser *accepts numeral tokens within a name*.
** Unchanged
- Lowercase delivery instructions *remain directions*; other document modes and output writers are unchanged.
** Edge cases
- *Multiple digits* remain in the name; =PARENT 3 (to Fiona)= keeps =to Fiona= separate.
** Decisions
- The change belongs in the *shared event parser*, before PDF, DOCX and ODT rendering.
** Next step
- Hand the checked candidate to the operator for the *closure decision*.

* Context

** Authority and baseline
- Authority :: The 2026-10-22 =BYPASS-GATE-7= request identifies =PARENT 3= as an example of any numeral-bearing character name. The preceding report gave =PARENT 2= and =PARENT 3 (to Fiona)= as incorrect DOCX outputs. This retrospective record was created after the emergency code change.
- Baseline :: [[file:../../docs/format-org.md][Org format reference]] defines level-four headings as character names with optional directions. [[file:../../docs/formats.md][Format overview]] describes shared character events and output fidelity. At =f8073c1=, =parseCharacterLine= stopped a name at the first later token whose initial rune was not uppercase; this treated numerals as directions.
- Scope :: Org script speaker cues and outputs consuming the shared event stream. Source files, cast entries and export styles are not changed.
- Exclusions :: Manuscript and letter modes, Markdown/Fountain speaker syntax, output layout and unrelated cue grammar.

* Acceptance Criteria

** AC066.1 - Numeral-bearing Org speaker names remain intact :ac:

- Criterion :: An Org speaker heading whose character name contains a numeral token *retains the complete name* in script exports, including multi-digit numerals.
- Boundary :: A following parenthetical or lowercase delivery instruction *remains a direction*. Existing unnumbered speaker cues remain unchanged.
- Proven by :: [[#rt-066-1][RT066.1 - Numbered cues through public conversion]] and [[#ot-066-1][OT066.1 - PDF and ODT output probe]].

* Edge Cases
- A *multi-digit numeral* remains one part of the character name.
- A *parenthesized lowercase phrase* still starts a direction after a numbered name.
- An *ordinary lowercase instruction* still starts a direction after an unnumbered name.

* Solution Design

** Shared Org speaker parser
- In =parseCharacterLine=, continue the name across tokens whose initial rune is uppercase or a Unicode digit. The first later token with neither property begins the direction as before. The existing event and renderer interfaces do not change.

** Security and operational impact
- No new dependency, external access, persistence, or unbounded parsing step is introduced. Existing conversion and output error handling remain.

* Delivery Handoff
