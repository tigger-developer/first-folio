* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- Stretched chapters retain *paragraph boundaries, indentation and uniform stretch*.
- The *full regression suite passes* with the current presets.
** Before
- A chapter-opening paragraph closes the stretch scope prematurely, joining
  later paragraphs and leaving them unstretched.
- Tests assume superseded defaults and omit stretched chapter openings.
** After
- Only the opening paragraph is flush; subsequent paragraphs remain separate
  and use the configured indent and body stretch.
** Changes
- Apply chapter-opening formatting *before* enclosing content in a stretch scope.
- Make header-test prerequisites explicit and align default assertions with
  the current British preset. Preserve the equivalent US mono size by inheritance.
** Unchanged
- Existing British defaults, source content, code/quote spacing and font roles
  remain unchanged. The broader stretch/hyphenation work is not accepted here.
** Edge cases
- Markdown and Org exercise both 100% and 160% stretch across five paragraphs.
** Decisions
- Correct the wrapper order; no new parser, dependency or configuration key.
** Next step
- Review the corrective implementation and retained evidence for operator closure.

* Solution Design
** Responsibilities and order
- The Go block renderer first marks the opening paragraph, then encloses the
  resulting content in the existing Typst stretch helper. Apply this order to
  both paragraph and raw-Typst block routes.
- Header-oriented fixture helpers enable the header in a lower configuration
  layer, so local explicit disablement still wins. Other fixture families set
  their enabled flag directly. Default assertions track the current preset.
- The US overlay inherits the identical mono size from the British base, satisfying
  the existing overlay-only-differences contract without changing rendered values.
** Verification rationale
- PDF geometry detects lost paragraph boundaries, indentation and stretch that
  string-only tests missed. The full suite protects unaffected role behaviour.
- No additional testing framework or production test interface is introduced.
** Security impact
- No new dependency, network, privilege or input trust boundary. Existing escaping
  and validation remain unchanged. Private manuscript evidence stays local.
