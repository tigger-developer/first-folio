* Full regression suite
=make test= returns exit 2. All failures are in the existing W054 office tests;
config, letter, manuscript, play, Typst and update-homebrew packages pass.
The unchanged W054 tests combine superseded expectations and representation
assumptions with stricter fidelity requirements:

- Content/body layout :: W054 expects the original full vertical gaps. Current
  British DOCX and ODT deliberately use the operator-approved compact spacing.
- Titles/running matter :: Separate intro masters/sections and exact title/footer
  positioning exceed this adoption's documented approximations.
- DOCX failure probes :: W054 expects Pandoc failures to affect DOCX; the retained
  native DOCX route does not invoke Pandoc.
- ODT units/columns :: Some assertions require literal mm values or physical
  column widths. ODT uses equivalent rounded points and relative column weights;
  RT058 checks the active configured 30mm cue ratio on a 112mm body width.
- ODT role/break attachment :: Some assertions require direct base-style use or
  automatic styles in content.xml. Generated named styles in styles.xml inherit
  the configured base roles and carry native breaks. RT058 resolves effective
  act breaks; the rendered three-act fixture has three pages and correct fields.
- ODT running-area geometry :: W054 compares page margins alone. The generated
  ODF combines page margins, running text height and running-area clearance.

W054 remains active. W055 - Org emphasis remains unclosed because the earlier
operator closure condition required a passing full suite. W058 does not change
that condition or claim the original W054 fidelity contract has been met.

The render probe isolated one ODF interoperability defect before delivery:
a generated metadata file was absent from the manifest. Replacing only the
manifest made LibreOffice open the same package. The reference now includes
metadata and its manifest entry; the regression checks XML member coverage.

* Author self-review
- Existing =docx_*.go=, PDF/Typst renderer and template files have no diff.
  Only the new ODT format dispatch was added to the existing conversion route.
- ODT uses the existing in-memory office layout, never a generated DOCX package.
  Word-shaped internal nodes remain a documented coupling, not a claim that a
  neutral common renderer has been introduced.
- Source/config values become encoded JSON or XML values. No source-controlled
  raw markup, image, filter, link or command is emitted to Pandoc. Fixed arguments
  and a private generated reference keep this separate from generic conversion.
- Resource/error review caught a promoted bytes.Buffer ReadFrom bypass of Write
  limits. Non-embedded bounded buffers now govern subprocess pipes. Executable
  regressions cover both a 220 KiB diagnostic and output above 128 MiB.
- Errors retain their cause when relabelling shared DOCX diagnostics for ODT.
  ZIP XML is checked incrementally; output is validated before publication.
- Declarative AST/style construction retains some functions above the 50-line
  review tripwire. XML validation, reference packaging and page masters are
  separate functions/files; further generic abstraction would obscure this
  intentionally bounded bridge.
- The shared inline parser retains legacy office limitations: single-asterisk
  Org bold is interpreted as italic, slash pairs in URLs can be interpreted as
  emphasis, and ordinary repeated spaces collapse in ODT. These were observed
  or verified in code and are documented in =docs/format-odt.md=.
- User editing over time (UT058.1), Word interoperability, exact frontmatter
  running variants and consolidation with DOCX remain unverified or out of scope.
