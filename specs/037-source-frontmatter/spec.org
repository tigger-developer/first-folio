* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- Markdown manuscripts carry *shared rendering configuration* alongside metadata.
** Before
- The parser retained metadata but *discarded folio/render configuration*.
** After
- Source mappings *merge recursively* between global and local configuration.
- TOC line spacing uses *native font-relative multipliers*, as body text does.
** Changes
- Source values use *existing effective-value validators* and can select style.
- Later input configuration is *rejected before output*.
** Unchanged
- Metadata handling, source-directory discovery, other input modes and body defaults
  *retain their existing behaviour*.
- Manuscript files and existing user preset edits *remain untouched*.
** Edge cases
- A local font size *preserves the source family*; same-property local values win.
- Null/scalar source namespaces *fail*. Omitted source properties inherit.
** Decisions
- Precedence is *presets, global, source, local, CLI*, lowest first.
** Next step
- Retain verification and independent review evidence for the *closure decision*.

* Edge Cases
- TOC multipliers use TOC font metrics, not body font metrics or point size
  alone. Body and TOC settings remain independent. Length-based TOC values
  are rejected even if the TOC is disabled; omission inherits 1.15 from presets.
- Only *present source namespaces* become configuration. Metadata and unrelated
  frontmatter keys are not injected into the shared configuration map.
- Empty namespace mappings are valid; *null/scalar namespaces are invalid*.
- Individual invalid source properties overridden by local properties follow
  *effective-value validation*, as in external configuration layers.
- Only the first input has frontmatter semantics. Later files are *body text*;
  a successfully decoded configuration mapping is rejected, while non-mapping
  or malformed YAML-like prose remains subject to ordinary Markdown parsing.
- *Absent source configuration preserves existing behaviour*. Org and other
  commands continue through their existing configuration and parsing paths.

* Solution Design
** Responsibilities and flow
- The manuscript input reader extracts configuration from the *first resolved
  Markdown input* before loading config, using the existing YAML decoder and
  delimiter handling shared with metadata parsing. Later configuration fails.
- =internal/config.Options.Source= supplies the optional map. The existing
  =deepMerge= inserts it after global style configuration and before local files.
  The existing style selector considers source between global and local values.
- Effective font/alignment validation remains in the shared loader; manuscript
  layout validation remains in =LoadConfig=. Parsing and rendering then use the
  resulting typed config and normal source metadata.
- No new dependency, configuration framework or alternate renderer is introduced.
  Structural review verifies the merge order and absence of direct source-value
  interpolation into templates outside the existing validated config path.
** Security impact
- Source YAML reaches the *existing configuration trust boundary*. Namespaces
  must be mappings; relevant final-value validators run before output. This does
  not claim new validation for properties that external YAML does not validate.
- No network calls, widened access or durable source edits. Private manuscript
  content stays local and outside tracked tests or review evidence.

** Preset continuation
- The British embedded preset now declares the existing effective heading
  defaults. Shared configuration merging and renderer fallbacks are unchanged.
- Preset inspection checks the public configuration catalogue; before/after
  rendering and existing tests check preservation. No new trust boundary,
  dependency, schema or access is introduced.
- Product documentation :: The preset is updated directly. The configuration
  reference already documents these supported properties and remains accurate;
  architecture, source schema and CLI help require no behavioural amendment.

** TOC spacing continuation
- Shared Go validation normalizes body and TOC positive finite multipliers
  before output. The TOC's empty-string fallback is removed so explicit empty
  values fail. The British base supplies 1.15; US inherits it.
- One Typst helper computes leading from measured cap-height/baseline line box
  plus native 0.65em leading, multiplied by the configured value. Body and TOC
  invoke it in their respective font contexts. TOC entries use that leading
  between blocks and within wrapped text. Part-gap-before remains a length.
- Existing length-based TOC fixtures are migrated to numeric values. The
  existing entry-separation test now asserts a doubled native interval.
- Compatibility :: Existing TOC length values require explicit migration; this
  is intentional consistency with the already established body contract.
  No copyright spacing or heading-position changes are included.
- Documentation :: The configuration reference records numeric defaults,
  independent font contexts and migration. Architecture, schema and CLI options
  are unchanged. No new dependency, trust boundary or access is introduced;
  strict validation prevents unvalidated spacing interpolation.
