*** Preliminary native-layout experiments, 2026-10-16

- Scope :: Temporary native packages only, before production implementation. Overall OT remains AMBER: the full feature comparison and inspection have not run.
- Versions :: Pandoc 3.9.0.2, Typst 0.14.2, LibreOffice 26.2.3.2. First Folio baseline =ec9955e=.
- Baseline :: A short frontmatter paragraph followed by the first chapter, with no requested break, produces one PDF page. The header is =FRONT-HEADER i= and the footer =BODY-FOOTER 1=. This confirms the existing renderer observes state at different positions for the two running bands; the mixed page must not simply be assigned one body variant everywhere.
- Master-page transition :: Assigning a different ODT master page to the body paragraph creates a second page despite =fo:break-before="auto"=. This candidate does not implement the continuous case.
- Conditional paragraphs :: Two conditional header/footer paragraphs reproduce the first mixed page, but the frontmatter header persists on the second body page. This candidate is insufficient; its first-page success is not a conformance result.
- Variable fields :: Native =text:variable-get= string fields switch from frontmatter header/body footer on the mixed page to body header/body footer on the next page. Native =text:page-variable-set= with adjustment zero plus =text:page-variable-get= displays body 1 then 2 without a physical-page reset. Combining distinct frontmatter/body number formats with this continuous route remains unproved.
- Parity :: A right-only ODT body master after a frontmatter page creates a blank physical page before the body. LibreOffice's default PDF export omits this blank. Export with =IsSkipEmptyPages=false= retains it: the body is physical page 3 and displays page 1. The retained rendering helper must explicitly preserve automatic blank pages.
- Displayed-number offset follow-up :: The temporary =custom-number.odt= uses native page-variable adjustment 41. Its PDF retains the intentional blank physical page 2 and displays =BODY-DISPLAY 42= on physical page 3. A separate =left-native-reset.odt= uses a left-only body master, native =style:page-number="1"= and a native page-number field: the body is physical page 2 and displays 1. Both PDF text outputs were checked again with =pdftotext -layout= after the operator approved the bounded ODT number-format transition exception. These establish native mechanisms, not a new arbitrary-start YAML setting or proof of every continuation policy.
- Contents refresh :: Plain Pandoc =--toc= output followed by headless PDF conversion leaves the DOCX contents empty and the ODT contents unpopulated. With 80 explicit native page-reference entries, ODT refreshes the references during conversion, including a contents continuation page. DOCX retains deliberately stale =999= reference values in the equivalent probe. Explicit field/index refresh is being tested; neither empty output nor stale references count as success.
- Explicit refresh follow-up :: A temporary LibreOffice Basic helper, invoked headlessly from the private profile, loads the DOCX with document macros disabled, calls =TextFields.refresh()= and =getDocumentIndexes().getByIndex(i).update()=, refreshes layout and exports PDF. The resulting contents spans three pages. All 80 extracted contents references match their actual physical heading pages. This establishes a local test mechanism, not a new exporter runtime dependency. Configured contents typography, continuation padding and body-number offsets remain separate checks.
- Temporary evidence :: Source packages, extracted XML, PDF outputs and the short PDF baseline are retained in the OS-allocated =folio-w063-layout-20261016-26948-z7f315= directory for the active experiment. A reproducible retained helper and final measurements are still required before this OT can be GREEN.
