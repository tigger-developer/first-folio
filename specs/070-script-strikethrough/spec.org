* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome
- *Script strikethrough renders* in PDF, DOCX and ODT from the supported Org and Markdown markers.
** Before
- The markers *remained literal* because the script-specific inline paths omitted strikethrough.
** After
- Org =+text+= and Markdown =~~text~~= *produce strikethrough* in body text and footnotes.
** Changes
- PDF uses Typst strike markup; DOCX and ODT use their *native strike properties*.
** Unchanged
- Existing emphasis, literal/code and text-conversion behaviour *remains unchanged*.
** Edge cases
- Markdown =~text~= *remains literal* because single tilde is outside the supported script syntax.
** Decisions
- The existing source-aware inline parser and output serializers are *extended without a new parser*.
** Next step
- Operator validation of representative PDF and office output remains required before closure.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem
- Rendered scripts expose Org and Markdown strikethrough delimiters instead of styling their enclosed text.

** Outcome
- Supported strikethrough markers render consistently across script PDF, DOCX and ODT output.

** Scope
*** In scope
- Org =+text+= and Markdown =~~text~~= in script event text and footnote definitions.
- PDF/Typst, DOCX and ODT rendered-output paths.
*** Out of scope
- Single-tilde Markdown strikethrough, Fountain syntax, text-format marker translation, manuscripts and letters.
*** Unchanged
- Bold, italic, underline, literal/code and footnote-reference semantics.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context
- Relevant components :: The script Typst translator maps source markers to escaped Typst content; the shared source parser produces typed inline nodes; DOCX serializes those nodes and ODT projects the same native properties through structured Pandoc JSON.
- Existing pattern :: Extend the source-aware emphasis dispatch and existing =Strikeout= inline node.

** High-level design
- PDF/Typst recognizes Org plus pairs only for Org input and double-tilde pairs only for Markdown input, emitting escaped =#strike= content.
- The script inline parser produces the existing =Strikeout= node for the same source-specific markers.
- DOCX maps =Strikeout= to =w:strike=; ODT projects that property to Pandoc =Strikeout= and the resulting native ODF style.
- Fountain and Markdown single tildes do not enter these branches.

** Design decisions and verification
*** Reuse the established inline model
- Decision :: Reuse =Strikeout= rather than adding a script-only node or parser.
- Verification :: [[#rt-070-2][RT070.2 - Office outputs contain native strike properties]] checks both office projections at their native output boundary.

** Routine details left to implementation
- Regular-expression names and local test-helper structure may follow existing conventions.

** Architecture impact
*** Security impact
- Threat boundary :: Unchanged; source text remains bounded untrusted input.
- Data and secrets :: No new storage, logging or external transmission.
- Access :: No new file, process or network access.
- Conclusion :: Existing escaping, nesting, expansion and package limits remain applicable.
