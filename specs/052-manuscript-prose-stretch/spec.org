* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- Body, quoted, inline-code and code-block text use *proportional glyph widths*.
** Before
- Body and quote stretch *selects a nearby font face* and can have no effect.
** After
- Each role scales its *normal-width face* without changing glyph height.
** Changes
- Body and quote rendering acquire *geometric stretch*.
** Unchanged
- Monospace keeps its existing scaling, spacing and indentation contracts.
- Headings, frontmatter, running bands, other modes and font defaults are outside scope.
** Edge cases
- Mixed font roles retain *independent ratios*; nested code is not scaled twice.
- Non-100% prose supports discretionary English hyphenation while preserving
  unbroken word widths, paragraph boundaries and independent code styling.
** Decisions
- Retain geometric scaling and add =folio.manuscript.hyphenation= with
  =true=, =false= and =auto=; the British base sets =auto= and US inherits it.
- Superseded initial decision :: The first implementation introduced no setting
  or dependency. The operator subsequently requested configurable hyphenation,
  including when text is stretched, under this same emergency ticket.
** Next step
- Retain regression and rendered evidence, independent reviews and user validation
  for the closure decision.

** Hyphenation decision history
- Word-level scaling can move a whole word to the next line where native
  paragraph layout would hyphenate it into the remaining space. A synthetic
  comparison demonstrated this initial limitation; it was not accepted.
- The operator requested a configuration parameter, then explicitly requested
  completion of the hyphenation change under the same emergency ticket.
- =false= disables automatic splitting; =true= permits it regardless of
  justification; =auto= permits it when =justify: true=. Permission does not
  require a word to be split if the line breaker finds another suitable layout.

* Edge Cases
- A single-width family must still widen or narrow; a condensed face must not
  compound geometric scaling. Whitespace is normalized to the normal face.
- A 100% prose ratio bypasses word boxing to preserve native line breaking.
- Extreme positive ratios retain existing validation; no new range is imposed.
- At non-100%, explicit breaks use English ASCII patterns, matching the existing
  English language default. Tokens with non-ASCII letters or over 128 letters
  stay whole. Break points that would alter ligatures or kerning are excluded.
  The discretionary hyphen itself uses Typst's native glyph width; source letters
  retain geometric scaling. These limits require visibility in documentation and UT.

* Solution Design
** Rendering responsibilities
- The existing Go block renderer wraps body paragraphs and Pandoc body blocks
  in a prose stretch scope only when body stretch differs from 100%.
- The quote show rule uses the same helper inside its own font context.
- The helper reads contextual stretch, normalizes each word to the 100% face,
  retains measured descent, and scales horizontally with reflow. Outer rules
  see the normalized stretch, preventing compounded nested scaling.
- Normalize inter-word spacing by the normal-face to selected-face space-width
  ratio. Existing mono rendering continues to own its independent scaling.
- The shared loader validates the new setting after deep merge. The manuscript
  renderer emits the Typst hyphenation setting in the body scope; mono explicitly
  disables it. The normal-width path retains native Typst behaviour.
- For stretched prose, Go embeds English patterns and exceptions and creates a
  sorted dictionary of document words and candidate offsets. The pinned
  =github.com/speedata/hyphenation v1.0.2= library applies TeX patterns locally.
  Generated Typst is self-contained, with no package download or font dependency.
- The Typst helper excludes shaping-sensitive offsets, scales the remaining
  pieces, and places a word joiner before each soft hyphen so inline boxes cannot
  break before the mark. Line and page breaking remain Typst responsibilities.
- Template ownership, CLI layering and validated font values remain as in
  [[file:../../docs/ARCHITECTURE.md][Rendering architecture]].
** Security impact
- One pinned CC0 Go dependency and vendored redistributable pattern data are
  added. The data's notice and source revision are retained. No runtime network,
  data exposure or access change. Dictionary keys are ASCII words and offsets
  are numeric; existing escaping and font validation remain in force.
- The library's substring search is bounded to words of at most 128 letters;
  longer tokens remain intact. Fixtures are synthetic.
