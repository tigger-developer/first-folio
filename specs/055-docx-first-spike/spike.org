#+TITLE: W055 - DOCX-first script export spike
#+STARTUP: overview
#+OPERATOR_SIGNOFF: Approved 2026-10-11, delegated scope alignment

* Question
Can a small, isolated DOCX adapter produce useful editable British, US stage-play
and screenplay documents, accepting documented layout compromises, while
preserving existing conversions?

* Scope and approach
- Export Org, Markdown and Fountain through the existing parsed and filtered
  script model. Preserve text, inline emphasis, cues, directions, headings,
  cast tables, footnotes, font roles and basic page geometry.
- Try a native Go ZIP/XML DOCX writer first. A single target permits a small
  serializer without a Pandoc process, intermediate document or package rewrite.
  Pandoc remains an independent reader for bounded interoperability checks.
- Use native editable paragraphs, tables, notes and page fields. Apply resolved
  configuration. Never convert script text to images.
- ODT is deferred. Exact title positioning and intro/body/facing-page running
  matter parity are not required. Record the actual support and approximations.
- Invalid content or unsafe geometry must fail before publication. Refuse
  terminal binary output without =--force= and reject source/target identity
  and destination symlinks. Retain old target bytes on pre-publication failure.
- No network, macros, embedded fonts or runtime external tools in the adapter.
  Reject XML-invalid text, bound source and generated XML/package sizes.

* Evaluation criteria
1. All nine source/style routes produce readable DOCX with ordered text and
   native editable structures. Empty and untitled sources also work.
2. Effective styles express configured fonts, spacing and speech geometry;
   partial configuration overrides and visibility switches remain effective.
3. CLI selection, redirected stdout, terminal protection and failure boundaries
   operate through the actual executable. No source/config mutation occurs.
4. Existing conversion tests retain their baseline results, and representative
   Org/Markdown/Fountain/Typst/PDF output matches the baseline under the same tools.
5. Pandoc reads generated DOCX; a bounded headless LibreOffice conversion checks
   import/render behaviour. Visual acceptance and editing in Word remain a UT.
6. Self-review records correctness, security, maintainability and evidence gaps.

** Author self-review
- Correctness: review found duplicate =pageBreakBefore= when an act begins the
  first body page. A failing assertion reproduced it; generation now deduplicates
  that property and retains its schema order. The assertion passes.
- Configuration: review found a root =1.5em= font size applied twice. A failing
  executable test expected 36 half-points; resolution now uses the 12-point root
  base exactly once and the test passes.
- Test fixture: macOS =script= propagates the guarded command's exit status.
  The terminal test now expects exit 1 for refusal and success for =--force=;
  this was a test expectation correction, not an exporter bypass.
- Security: XML encoding escapes text; invalid XML characters are rejected.
  No external relationships, macros or subprocesses are generated. Sources are
  bounded at 32 MiB, events at 50,000, inline segments at 100,000, expanded text
  at 32 MiB, and generated XML/package bytes at 128 MiB. These are output/work
  bounds, not a claim that process memory is limited to 128 MiB.
- Publication: build before writing, refuse source identity/hardlinks and
  destination symlinks, stage at mode 0600 beside the destination, then rename.
  Recheck before rename; this does not promise protection against adversarial
  concurrent parent-directory changes. No durability/fsync guarantee is made.
- Maintainability: five adapter files separate XML, styles, content, pages and
  publication. Some content/style dispatch functions exceed the usual size
  guideline; explicit format mapping was retained rather than introducing a
  general document framework. This remains author judgement, not independent review.
- Shared dispatch now selects configuration/format before reading the source,
  so error precedence can change when multiple inputs are invalid. Existing
  successful routes match the baseline; parsers, renderer and templates are unchanged.

* Findings
The experiment demonstrates useful editable DOCX for the reduced contract.
It does not establish full-fidelity W054 office export or product approval.

| Area | Implemented support | Limitation |
|------+---------------------+------------|
| Sources | Org, Markdown, Fountain; three script styles | Export only; no DOCX reader |
| Content | Ordered text, emphasis, cues, directions, props, cast, headings, native notes | Existing parser interpretation is retained |
| Speech | British native table; US/screenplay native paragraphs | Reader pagination may differ; continuation cues are not repeated |
| Fonts | Role families, size, bold/regular, italic, tracking, stretch | Oblique approximates italic; unsupported weights fail |
| Geometry | Paper, margins, indents, spacing, column widths, act breaks | Line spacing uses 1.2; negative before/after space clamps to zero with warning |
| Title | Dedicated/compact title, subtitle, author, date and version | Approximate vertical placement; date/version are in-flow, not bottom footer slots |
| Running matter | Native first/odd/even parts, PAGE/NUMPAGES, first-page suppression | Single section; body variant also covers intro, with warning; no numbering reset |
| ODT | One-off Pandoc conversion probed | Substantial layout loss; no CLI ODT route |

Recommendation: retain this native adapter as the candidate for a narrower
DOCX product change, subject to Word user validation and an agreed support
contract. The original Pandoc-first serializer and a direct ODT writer were
not implemented; neither is needed to answer this single-target experiment.
Product help, release documentation and original W054 ticket reconciliation
remain outside this spike. Existing W054 specification and tests remain intact.
