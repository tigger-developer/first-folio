** Outcome
- Script, letter and manuscript PDF and Typst output *apply configured font stretch as visible horizontal scaling*.
** Before
- Script Typst contained the configured percentages, but fonts without matching width faces *rendered every tested role at normal width*.
** After
- Every applicable font role *renders at its configured width ratio* while retaining height, baseline and word wrapping.
** Changes
- The script, letter and manuscript templates *geometrically scale words and spaces* from the normal-width face.
** Unchanged
- *DOCX and ODT remain native and editable* and retain their format-native text scaling.
** Edge cases
- =100%= stays at normal width; compression and expansion work independently for adjacent roles.
** Decisions
- Each Typst template uses the same geometric contract across all of its explicit typography roles; configured percentages never select a width face.

* Edge Cases
- *Compression and expansion coexist* within a single dialogue block.
- *Spaces scale with words*, so multiword instructions and dialogue retain proportional spacing.
- *Word-level scaling preserves wrapping opportunities* instead of scaling one already-laid-out paragraph box.
- *Normal width is an identity path* and does not introduce a new box around each word.

* Solution Design

** Geometric Typst helpers
- Each template normalizes the selected face to =100%= stretch, scales each non-space token horizontally by the configured ratio with reflow, preserves its measured descent as the box baseline, and scales inter-word spacing by the same ratio.
- Explicit typography roles retain configured family, size, weight, style and tracking. Role state prevents an enclosing body rule from scaling nested monospace or another explicit role a second time, including when both ratios are numerically equal.

** Output boundaries
- The existing PDF YAML cascade and validated font values remain authoritative. PDF compilation, content escaping and error propagation do not change. DOCX and ODT writers retain their native editable stretch properties.

** Security and operational impact
- No dependency, external service, persistence or new input surface is introduced. Scaling operates on already escaped template content with the existing input and compilation bounds.
