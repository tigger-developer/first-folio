* Specification Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- *Outcome:* Every configurable text role uses the same =font= block across
  scripts, letters, and manuscripts.
- *Before:* Font properties use inconsistent scalar, prefixed, and boolean keys;
  script and manuscript modes also load separate British and US baselines.
- *After:* One exhaustive British runtime base supplies explicit font defaults
  for every role, while US and screenplay files contain only their differences.
- *Changes:* The public font schema becomes a breaking six-property block;
  legacy font keys fail; the existing regression pack is migrated without
  losing behavioural coverage.
- *Unchanged:* Configuration discovery and precedence, CLI option names, source
  conversion, document semantics, layout, and supported outputs remain intact.
- *Edge cases:* Partial higher-layer blocks merge by property; omitted role
  blocks reveal the lower layer; roles never inherit fonts from other roles.
- *Decisions:* Configuration layers are the only inheritance mechanism; no
  legacy aliases or role-to-role font inheritance are supported.
- *Next step:* Definition gate, then operator sign-off.

The summary above accurately and completely represents the detailed
specification below.

-----

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

First Folio exposes the same typography concepts through incompatible public
YAML shapes. Some roles support only family and size, some add weight or style,
and script roles use =bold= and =italic= booleans. Consequently, a valid font
variant such as bold extended cannot be configured consistently for every role.

The runtime also selects separate British script and manuscript base files.
This prevents one shipped file from being both the actual default authority and
the exhaustive configuration reference promised to users.

** Outcome

First Folio has one consistent, breaking font-configuration contract and one
exhaustive British runtime base for script, letter, and manuscript publishing.

** Scope

*** In scope

- Replace every public font-family, size, weight, stretch, style,
  letter-spacing, bold, and italic role setting with the same nested =font=
  block.
- Make =presets/british.yaml= the exhaustive lowest-precedence runtime base for
  script, letter, and manuscript modes.
- Make =presets/us.yaml= and =presets/screenplay.yaml= limited overlays that
  contain only values differing from the British base.
- Reject the retired font schema and malformed new font blocks before producing
  output.
- Migrate affected regression tests while retaining every maintained
  behavioural check and its requirement lineage.
- Update the public configuration reference, examples, and migration guidance.

*** Out of scope

- Source-frontmatter configuration or any new configuration-precedence layer.
- New font properties, named typography styles, user-defined inheritance, or an
  OpenType feature registry.
- Changes to source parsing, document semantics, pagination, or non-typographic
  layout.
- A language or runtime migration.

*** Unchanged

- CLI flags remain the highest-precedence layer, followed by nearest local
  style-specific configuration, nearest local base configuration, global
  style-specific configuration, global base configuration, the selected built-in
  style overlay, and the British base.
- =folio convert --font= and =--font-size= retain their public meanings.
- Org, Markdown, and Fountain stage-play conversion remains bidirectional; Typst
  and PDF remain rendering outputs.
- Org letter PDF generation and Markdown or Org manuscript Typst/PDF generation
  retain their non-font behaviour.
- First Folio continues to tolerate unrelated top-level namespaces such as
  =yapper=; strict rejection is confined to First Folio font configuration.

** Constraints and dependencies

- The canonical British file must be valid user YAML and valid as the embedded
  runtime base. An unchanged copy at a supported user configuration location
  must not change effective output.
- The approved British, US, and screenplay rendered appearance is the migration
  baseline. Generated Typst text may differ where explicit regular font values
  replace omission, but observable rendering must not.
- Typst remains the PDF renderer and Pandoc remains the rich manuscript
  conversion boundary described by the architecture.

** Decisions

- This is an intentional breaking configuration change for the sole current
  user. The application accepts no legacy font aliases after delivery.
- Every =font= block has exactly these public properties: =family=, =size=,
  =weight=, =stretch=, =style=, and =letter-spacing=.
- The British base assigns all six properties explicitly for every font role.
  No font role obtains an omitted property from another role.
- A higher-precedence layer may provide a partial =font= block. Deep merge
  preserves unspecified properties from the same role in lower layers.
- Omitting a role's entire =font= block in an overlay leaves that role's lower
  layer block unchanged.
- The British file lists every accepted public configuration property. Runtime
  defaults are assigned; optional or source-derived values are shown as
  commented options with their source or absence semantics.
- US and screenplay are both limited overlays. The current split manuscript
  baseline and split US overrides are retired.
- The existing =presets/british.yaml= was produced under the abandoned draft.
  Delivery must reconcile it against current runtime baselines and approved
  behaviour rather than treating it as requirement authority.

** Unresolved blockers

- None.

:PROPERTIES:
:CUSTOM_ID: ac-039-1

- *Criterion:* Given any configurable font role in script, letter, or manuscript

  =stretch=, =style=, and =letter-spacing=, and each property affects only that

  use =presets/british.yaml= as their shared lowest-precedence configuration;
  copying that file unchanged to a supported user location leaves the effective

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** Partial block in a higher layer

- *Condition:* A user layer sets only one property in a role's =font= block.
- *Required behaviour:* The other five properties remain those of the same role
  in lower layers.
- *Covered by:* [[#ac-039-3][AC039.3 - Configuration-layer inheritance only]]
  and [[#rt-039-3][RT039.3 - Preserve lower-layer font properties]].

** Entire role block omitted from an overlay

- *Condition:* US, screenplay, global, or local configuration does not contain a
  role's =font= block.
- *Required behaviour:* The lower-layer block for that role remains unchanged;
  no other role is consulted.
- *Covered by:* [[#ac-039-3][AC039.3 - Configuration-layer inheritance only]]
  and [[#rt-039-4][RT039.4 - Verify minimal style overlays]].

** Retired or malformed font shape

- *Condition:* First Folio configuration contains an old scalar, suffix, or
  boolean font key, or a new =font= mapping with an unknown, null, empty, or
  invalid property.
- *Required behaviour:* Loading fails at the public command boundary before an
  output artefact is created.
- *Covered by:* [[#ac-039-5][AC039.5 - Clean breaking failure boundary]] and
  [[#rt-039-5][RT039.5 - Reject invalid font configuration]].

** Unrelated namespace

- *Condition:* Configuration contains a =yapper= block or an otherwise tolerated
  unrelated top-level key.
- *Required behaviour:* Existing tolerance remains; font-schema validation does
  not claim ownership of another namespace.
- *Covered by:* [[#ac-039-6][AC039.6 - Existing publishing behaviour remains]]
  and [[#rt-039-6][RT039.6 - Preserve public publishing workflows]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- *Relevant components:* Embedded preset assets, the shared layered loader,
  typed manuscript configuration, script and letter configuration consumers,
  and the three Typst rendering paths.
- *Ownership boundary:* First Folio owns =folio= configuration, validation,
  effective font values, Typst data, and output lifecycle. Typst owns font
  discovery and PDF typesetting; Pandoc owns supported manuscript conversion.
- *Existing pattern:* Preserve map-based deep merging and source-directory
  discovery, but replace split bases and role-specific font normalization.

** High-level design

*** Alternatives rejected

- *Role-to-role inheritance:* Rejected because manuscript roles do not form a
  clean parent hierarchy and hidden fallbacks make the effective font harder to
  predict than explicit base values.
- *Compatibility aliases:* Rejected because the operator selected one clean
  breaking migration and is the sole current user.
- *Separate script and manuscript bases:* Rejected because duplicated defaults
  can drift and cannot provide one copyable runtime reference.

*** Flow

1. Load =presets/british.yaml= for every mode, then apply the selected US or
   screenplay overlay when applicable.
2. Apply global, global style-specific, nearest local, nearest local
   style-specific, and CLI layers through the existing precedence and
   property-level deep merge.
3. Validate each First Folio font node, materialize complete role-local font
   values, and pass those values to the existing render path.
4. Render Typst or PDF through the existing process and preserve the current
   output-creation boundary on failure.

*** Interfaces and configuration

- *Font interface:* Every font role uses:

  #+begin_src yaml
  font:
    family: Libertinus Serif
    size: 12pt
    weight: regular
    stretch: 100%
    style: regular
    letter-spacing: 0em
  #+end_src

- *Covered roles:* Root body and heading; letter body; script title-page items,
  speech roles, stage directions, transitions, and section headings; manuscript
  body, heading, monospace, quoted block, title-page items, running header,
  running footer, contents body and heading, and copyright body and label.
- *Property semantics:* Preserve supported family and Typst length forms;
  named or numeric weights; percentage stretch including the established numeric
  shorthand; =regular=, =italic=, or =oblique= style; and existing positive or
  negative letter-spacing lengths.
- *CLI compatibility:* =folio convert --font= writes the effective root
  =font.family= and =--font-size= writes =font.size= without changing the flag
  surface or precedence.
- *Configuration compatibility:* Existing configuration files require a one-time
  schema migration. No dual decoder or deprecation interval is provided.

*** Data and state

- Replace the separate British script and manuscript files with one active
  =presets/british.yaml=.
- Replace split US files with =presets/us.yaml= and retain screenplay as
  =presets/screenplay.yaml=, each containing only differences.
- Use one reusable, presence-aware internal font value for validation and
  rendering. Presence is required while merging partial higher layers; the
  effective value for every role is complete after the British base is applied.
- Remove normalization that copies font values between roles. Retain ordinary
  same-path deep merge across configuration layers.

*** Failure behaviour

- Validate First Folio font configuration after layers are merged but before
  any requested output is opened or written.
- Report the complete YAML path and invalid value or shape on standard error and
  return non-zero.
- Do not partially create PDF, Typst, or letter batch outputs after a
  configuration failure.

** Architecture impact

*** Security impact

- *Threat boundary:* Unchanged. The change parses the same trusted and untrusted
  local YAML locations already accepted by the application.
- *Data and secrets:* No new data, secret, log, network, or persistence path is
  introduced.
- *Access:* File-discovery boundaries and process privileges remain unchanged.
- *Conclusion:* Strict path-aware validation reduces ambiguous input handling;
  no additional security mitigation is required.

*** Other relevant qualities

- *Reliability:* One runtime base removes drift between script and manuscript
  defaults. Regression lineage and public-boundary tests protect the breaking
  migration.
- *Performance:* The additional small mapping validation is negligible beside
  document conversion and Typst rendering.
- *Operability:* Release notes and configuration migration guidance must call
  out the breaking schema. Rolling back the executable also requires restoring
  an old-shape user configuration.
- *Accessibility:* The exhaustive copyable YAML keeps every option discoverable
  without reading implementation code.
- *Portability:* Existing embedded assets and external Typst/Pandoc boundaries
  remain unchanged.
- *Maintainability:* One block type, one British base, and limited overlays
  remove repeated defaults and role-specific typography paths.
