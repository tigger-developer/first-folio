#+SUBTITLE: Bug analysis and proposed solution
#+STARTUP: overview

* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- Primary bug :: *Inline monospace text does not apply its configured font
  stretch* on an affected manuscript rendering path. Restore application of
  =folio.manuscript.mono.font.stretch=; this is the operator's original issue.
- Supporting repairs :: Close the related gaps in the *six existing font
  attributes* found during investigation. These findings support the original
  bug repair; they do not replace it or introduce new features.

** Before

- Confirmed reproduction :: Inline monospace text in a section heading remains
  *72pt wide at both 100% and 75% stretch*, despite the test font having both
  widths. The renderer *omits the configured stretch* from that inline span.
- Evidence limit :: Paragraph inline code responds to stretch in the same
  fixture. That *does not establish that the operator's original example works*;
  the exact reported case has not been reproduced. See [[#diagnosis][the recorded reproduction]].
- Supporting findings :: Section code also omits style and letter spacing;
  numeric weight fails compilation. Default part/chapter title code emits empty
  font values, and manuscript headings override configured size and weight.

** After

- Inline monospace text *uses the configured stretch* through the existing
  monospace font rule, selecting the requested available font width.
- Monospace content and ordinary heading text *use their complete role fonts*.
- Tests check *the affected content*, including its table-of-contents appearance.

** Changes

- Reuse the inline-raw font rule and apply the heading font at the semantic
  heading element; strengthen regression coverage.

** Unchanged

- Keep configuration keys, defaults, layering, parsing, casing, outline
  inclusion, code-block spacing, and Typst's font-selection semantics.
- The other active font roles keep their current application. No consumer is
  invented for the unused shared script heading font.

** Edge cases

- Preserve literal code, enclosing emphasis, and role isolation; handle numeric
  weights, partial overrides, and fonts without the requested width.

** Decisions

- The operator constrained the repair to *existing font attributes*, excluding
  new features. The earlier proposed casing change is superseded.
- Production implementation has not been requested; this remains a definition.

** Next step

- Review the revised definition and its expanded diagnostic evidence, then
  finalize the definition before normal delivery.

** Cause and existing coverage

1. [[file:../../internal/manuscript/parser.go][The parser]] converts ordinary prose and
   fenced blocks through Pandoc to Typst raw content. Section headings become
   =section= blocks.
2. [[file:../../internal/manuscript/render.go][The renderer]] sends section text through
   =typstInline= and =renderInlineMarkup=. The backtick branch generates
   =#text= with *only family, size, and weight*. It drops stretch, style, and
   letter spacing; numeric weights are also emitted as quoted strings.
3. [[file:../../templates/manuscript.typ][The template]] applies the complete font block
   to =raw.where(block: false)=. The explicit =#text= emitted for section code
   *bypasses that rule*. Its missing properties come from surrounding text.
4. [[file:../../internal/manuscript/font_test.go][The existing manuscript font test]]
   searches the whole emitted document for the changed property marker.
   Its =mono.font/stretch= case *passed at the defective baseline*, because
   template rules already contain that marker. It does not verify its use by
   the affected content. This is a gap in
  [[file:../039-unified-font-configuration/spec.org::#rt-039-1][RT039.1 - Exercise every public font role]].

5. Part/chapter =as-written= titles call the inline helper with =Config{}=,
   producing *invalid empty font arguments* for code. Their =upper= route
   preserves backtick delimiters for Typst and already uses the raw-content rule.
6. The manuscript template wraps semantic headings in =text=. Typst's heading
   styles then *override size and weight*: a configured =13.5pt= / =medium=
   becomes =18.9pt= / =bold= for parts, =16.2pt= / =bold= for chapters,
   and =13.5pt= / =bold= for sections.

** Operator scope clarification and title behaviour

- Current path :: Part and chapter headings pass through =caseTransform=.
  Its =as-written= path calls =typstInline(text, Config{})=, so a backtick
  span receives *empty font values*, including an invalid empty size literal.
  The British defaults select =as-written= for both heading kinds.
- Corrected observation :: =upper= uppercases the whole composed heading,
  including code letters. Its escaping helper leaves backticks intact, so Typst
  renders that content as raw monospace text using the complete font rule.
  The earlier claim that this path lacked monospace interpretation is superseded
  by the compiled probe in the all-font check.
- Operator direction :: On 2026-09-12 the operator required a bug repair
  narrowly scoped to the font attributes common to current font definitions,
  then requested checking all font objects and attributes.
- Required behaviour :: Repair code in =as-written= part/chapter titles and
  section headings. *Preserve the uppercase branch*, including uppercase code
  letters. Both title modes use the existing monospace font rule after repair.
- Outline behaviour :: Existing title text and casing appear in the table of
  contents. Code retains its mono font; ordinary entries retain the TOC font
  and the existing =toc.part-bold= option. Heading fonts must not leak into
  outline entries or running-header/footer roles.
- Superseded proposal :: Uppercasing only surrounding title text while keeping
  code letters unchanged would introduce new casing behaviour. That earlier
  recommendation is withdrawn under the operator's font-only boundary.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Recommended change

1. Make the backtick branch of =renderInlineMarkup= emit *inline Typst raw
   content*, using a correctly escaped string and =block: false=.
2. Let the existing =raw.where(block: false)= template rule apply
   =folio.manuscript.mono.font= through =manuscriptFontArgs=. It already maps
   all six properties, including normalized numeric weights and regular style.
3. Remove the now-unnecessary family/size/weight plumbing from inline rendering
   and its recursive calls. Preserve parsing, ordinary-text transformations,
   and the uppercase branch of =caseTransform=. The =as-written= branch then
   calls the simplified helper without constructing an empty configuration.
4. Apply =manuscriptFontArgs(Heading.Font)= through a heading *show-set text
   rule*, overriding Typst's default heading font values at the heading element.
   Preserve semantic heading bodies, levels, and outline flags. Do not embed
   heading-specific styling in the stored body, because outline entries reuse
   that body and must retain the TOC role font.
5. Strengthen regression assertions at the actual content boundary. In
   =docs/config.md=, explain stretch as *font-width selection* and distinguish
   it from letter spacing, without changing the accepted value domain.

** Feasibility evidence and alternatives

- Bounded probe :: In temporary generated Typst only, replace the section's
  incomplete =#text(...)[SECTIONPROBE]= with
  =#raw("SECTIONPROBE", block: false)=. Compiling the 100% and 75% cases changed
  section-code widths from *72.00pt to 49.92pt*, respectively. The paragraph
  and block measurements were unchanged from the reproduction table.
- Heading probe :: A heading show-set rule in temporary generated output
  restored the configured =13.5pt= / =medium= at all three heading levels,
  while ordinary TOC entries retained =10pt= / =regular=. See the
  [[file:font-rendering-check.org][all-font check]] for the diagnostic method and limits.
- Evidence boundary :: This validates the template route for that fixture;
  *production code was not changed*. Escaping, combined styles, other headings,
  and full regression validation remain delivery work.
- Alternative :: Passing the full font value into =renderInlineMarkup= and
  serializing all six arguments would also address the omission. It retains
  two formatting routes and requires handling =caseTransform='s current
  =Config{}= call. Reusing the existing raw-content rule avoids that duplication.
- Rejected scope :: Artificial horizontal scaling changes the external font
  contract and text-layout behaviour; it is not proposed for this defect.

** Architecture and safety

- Ownership :: Go continues to parse and emit content; the existing Typst
  template owns monospace styling. *No new dependency or runtime* is needed.
- Security :: Source text remains untrusted content. Escape quotes, backslashes,
  and control characters for a Typst string using the established escaping
  utility; do not insert code contents as executable Typst. No new filesystem,
  network, secret, or access boundary is introduced.
- Reliability :: One role rule reduces drift; content-specific tests expose
  omissions that whole-document marker searches miss.
- Compatibility :: Accepted configuration and source formats remain unchanged.
  Corrected typography may change line wrapping where a property was ignored.
- Performance and portability :: The change uses existing rendering facilities;
  no material runtime-cost or platform change is expected. Persistent tests
  must not depend on privately installed fonts; local font-dependent visual
  evidence belongs in the user test.
