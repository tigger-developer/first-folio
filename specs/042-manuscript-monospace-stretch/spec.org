* Apply manuscript monospace font stretch consistently
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- Outcome :: Manuscript inline code *uses the configured monospace font*,
  including stretch, wherever the supported renderer emits it.
- Before :: A reproduced *section-heading path omits stretch*, style, and
  letter spacing. Paragraph code and fenced blocks already receive stretch.
- After :: Inline code *uses the existing template rule* for all six font
  properties. Regression evidence checks the affected content itself.
- Changes :: Replace the incomplete inline font emission with *inline raw
  content*; strengthen behavioural coverage and explain font-width selection.
- Unchanged :: Configuration keys, defaults, layering, source syntax, ordinary
  text, code-block layout, and Typst's font-selection semantics remain intact.
- Edge cases :: Numeric weights, partial font blocks, nested emphasis, literal
  special characters, and fonts without another width require coverage.
- Decisions :: This is a *proposal for review*. Analysis and specification
  writing are authorized; production implementation has not been requested.
- Next step :: Resolve *part/chapter title scope and uppercase-code behaviour*,
  then finalize the definition and operator sign-off before normal delivery.

** Report and authority

- Intake :: [[file:../../docs/work.org::#w-042][W042 - Manuscript monospace font stretch is not applied]].
  The operator reported that =folio.manuscript.mono.font.stretch= is not
  implemented, then requested analysis and a proposed solution in this spec.
- Controlling requirement :: [[file:../039-unified-font-configuration/spec.org::#ac-039-1][AC039.1 - One uniform font block]]
  requires all six font properties to affect their selected role and explicitly
  includes =folio.manuscript.mono.font=. This proposal *repairs that contract*;
  it does not introduce another font schema.
- Project :: [[file:../../.sdlc/project.yaml][Project profile]],
  [[file:../../README.md][First Folio overview]],
  [[file:../../docs/ARCHITECTURE.md][Architecture and rendering ownership]], and
  [[file:../../docs/config.md][Configuration reference]].
- Source contracts :: [[file:../../docs/format-manuscript-markdown.md][Markdown manuscript syntax]]
  and [[file:../../docs/format-manuscript-org.md][Org manuscript syntax]].
- External semantics :: [[https://typst.app/docs/reference/text/text/#parameters-stretch][Typst font stretch]]
  selects a width available within a font family. A missing width uses the
  nearest available face; *arbitrary geometric scaling is not promised*.

** Reproduction and observed results
:PROPERTIES:
:CUSTOM_ID: diagnosis
:END:

- Baseline :: Commit =5108af665c0010b8f5ea72529de0106df8b89187=,
  W042 bug-report checkpoint, tested on 2026-09-11.
- Environment :: macOS arm64; Go 1.26.3; Pandoc 3.9.0.2; Typst 0.14.2;
  Poppler =pdftotext= 26.04.0. A fresh binary was built from this revision.
- Setup :: Two temporary source directories each contained a copy of
  =presets/british.yaml= as =script.yaml=. Only the monospace family and
  stretch were changed: =Iosevka Custom=, at =100%= or =75%=. Size remained
  =10pt= and weight remained =regular=. =typst fonts --variants= confirmed
  that this installed family exposes both normal and condensed widths.
- Input :: The following Markdown, plus its equivalent Org input using
  =* Part=, =** Probe=, =*** Section=, verbatim spans, and a source block:

#+begin_src markdown
## Probe

Prose `INLINEPROBE` control.

### Section `SECTIONPROBE`

```
BLOCKPROBE
```
#+end_src

- Procedure :: Run =folio manuscript sample.md output.typ= and
  =folio manuscript sample.md output.pdf=; repeat for Org and each configuration.
  Extract word bounds with =pdftotext -bbox output.pdf output.html=.
- Result :: *Both source formats produced the same measured widths*:

| Content marker | Width at 100% | Width at 75% |
|----------------+---------------+--------------|
| INLINEPROBE    | 66.00pt       | 45.76pt      |
| SECTIONPROBE   | 72.00pt       | 72.00pt      |
| BLOCKPROBE     | 60.00pt       | 41.60pt      |

- Interpretation :: *Section-heading code ignores the requested width* in
  this reproduction; paragraph and block code select a narrower face.
- Single-width control :: With =Libertinus Mono= at =100%= and =150%=,
  the first-page SVG outputs were byte-identical. The installed font inventory
  listed only normal-width faces for that family. This is consistent with
  Typst's documented width selection and *does not establish a Folio defect*
  for that control.
- Limit :: The operator's original source construct, font family, and value
  have not been supplied. The synthetic reproduction *establishes a defect*
  but does not establish the cause of every possible reported no-change case.

** Cause and existing coverage

1. [[file:../../internal/manuscript/parser.go][The parser]] converts ordinary prose and
   fenced blocks through Pandoc to Typst raw content. Section headings become
   =section= blocks.
2. [[file:../../internal/manuscript/render.go][The renderer]] sends section text through
   =typstInline= and =renderInlineMarkup=. The backtick branch generates
   =#text= with *only family, size, and weight*. It drops stretch, style, and
   letter spacing; numeric weights are also emitted as quoted strings.
3. [[file:../../templates/manuscript.typ][The template]] applies the complete font block
   to =raw.where(block: false)=. The explicit =#text= emitted for section code
   *bypasses that rule*. Its missing properties come from surrounding text.
4. [[file:../../internal/manuscript/font_test.go][The existing manuscript font test]]
   searches the whole emitted document for the changed property marker.
   Its =mono.font/stretch= case *passed at the defective baseline*, because
   template rules already contain that marker. It does not verify its use by
   the affected content. This is a gap in
   [[file:../039-unified-font-configuration/spec.org::#rt-039-1][RT039.1 - Exercise every public font role]].

** Proposed scope and constraints

- Repair *inline monospace rendering through the shared template rule*,
  including its six existing font properties. Retain the current treatment of
  ordinary prose, chapter/part casing, block spacing, and source parsing.
- Preserve [[file:../039-unified-font-configuration/spec.org::#ac-039-3][AC039.3 - Configuration-layer inheritance only]]
  and [[file:../039-unified-font-configuration/spec.org::#ac-039-5][AC039.5 - Clean breaking failure boundary]].
- Exclude new scaling controls, font installation, font-family rewriting,
  configuration-schema changes, and unrelated manuscript defects.
- Initial assessment :: The initial proposal identified no blocking product
  decision. That assessment is *superseded by the title-semantics question
  below*; a different original symptom may also require investigation.

** Unresolved part/chapter title semantics

- Current path :: Part and chapter headings pass through =caseTransform=.
  Its =as-written= path calls =typstInline(text, Config{})=, so a backtick
  span receives *empty font values*, including an invalid empty size literal.
  The British defaults select =as-written= for both heading kinds.
- Uppercase path :: =upper= uppercases and escapes the heading as ordinary
  content; it does not interpret the code span as monospace content.
- Decision required :: Whether part/chapter title code belongs in this repair,
  and what uppercase conversion should do to its text and font. The general
  inline-code criterion below *cannot authorize a silent behaviour choice*.
- Recommendation :: Include title code, uppercase only surrounding title text,
  and preserve literal code text with its monospace formatting. This is a
  proposal, not an operator-approved change to uppercase-title semantics.
- Definition boundary :: Resolve the decision before delivery. Reconcile the
  summary, acceptance criterion, tests for both casing modes, and outlined
  title appearance in the table of contents with the selected behaviour.

** AC042.1 - Inline code receives its complete monospace font
:PROPERTIES:
:CUSTOM_ID: ac-042-1
:END:

- Criterion :: Supported manuscript inline code, including code within section
  headings, *uses all six effective monospace font properties*. Stretch selects
  the requested available width according to Typst's semantics.
- Relationship :: Regression-specific application of
  [[file:../039-unified-font-configuration/spec.org::#ac-039-1][AC039.1 - One uniform font block]].
- Proven by :: [[#rt-042-1][RT042.1 - Verify font properties at inline content]] and
  [[#ut-042-1][UT042.1 - Compare rendered monospace widths]].

** AC042.2 - Monospace changes preserve neighbouring content
:PROPERTIES:
:CUSTOM_ID: ac-042-2
:END:

- Criterion :: Changing the monospace font *does not change the effective font
  of neighbouring ordinary text*. Literal code characters, supported enclosing
  emphasis, heading casing, and existing block layout remain preserved, allowing
  wrapping and pagination changes caused by the corrected code width.
- Proven by :: [[#rt-042-2][RT042.2 - Preserve literals and role isolation]] and
  [[#ut-042-1][UT042.1 - Compare rendered monospace widths]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Recommended change

1. Make the backtick branch of =renderInlineMarkup= emit *inline Typst raw
   content*, using a correctly escaped string and =block: false=.
2. Let the existing =raw.where(block: false)= template rule apply
   =folio.manuscript.mono.font= through =manuscriptFontArgs=. It already maps
   all six properties, including normalized numeric weights and regular style.
3. Remove the now-unnecessary family/size/weight plumbing from inline rendering
   and its recursive calls. Preserve parsing, ordinary-text transformations,
   and the uppercase branch of =caseTransform=.
4. Strengthen regression assertions at the actual content boundary. In
   =docs/config.md=, explain stretch as *font-width selection* and distinguish
   it from letter spacing, without changing the accepted value domain.

** Feasibility evidence and alternatives

- Bounded probe :: In temporary generated Typst only, replace the section's
  incomplete =#text(...)[SECTIONPROBE]= with
  =#raw("SECTIONPROBE", block: false)=. Compiling the 100% and 75% cases changed
  section-code widths from *72.00pt to 49.92pt*, respectively. The paragraph
  and block measurements were unchanged from the reproduction table.
- Evidence boundary :: This validates the template route for that fixture;
  *production code was not changed*. Escaping, combined styles, other headings,
  and full regression validation remain delivery work.
- Alternative :: Passing the full font value into =renderInlineMarkup= and
  serializing all six arguments would also address the omission. It retains
  two formatting routes and requires handling =caseTransform='s current
  =Config{}= call. Reusing the existing raw-content rule avoids that duplication.
- Rejected scope :: Artificial horizontal scaling changes the external font
  contract and text-layout behaviour; it is not proposed for this defect.

** Architecture and safety

- Ownership :: Go continues to parse and emit content; the existing Typst
  template owns monospace styling. *No new dependency or runtime* is needed.
- Security :: Source text remains untrusted content. Escape quotes, backslashes,
  and control characters for a Typst string using the established escaping
  utility; do not insert code contents as executable Typst. No new filesystem,
  network, secret, or access boundary is introduced.
- Reliability :: One role rule reduces drift; content-specific tests expose
  omissions that whole-document marker searches miss.
- Compatibility :: Accepted configuration and source formats remain unchanged.
  Corrected typography may change line wrapping where a property was ignored.
- Performance and portability :: The change uses existing rendering facilities;
  no material runtime-cost or platform change is expected. Persistent tests
  must not depend on privately installed fonts; local font-dependent visual
  evidence belongs in the user test.
