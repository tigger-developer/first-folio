* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- Body line spacing uses *multipliers of the font's normal baseline interval*.
** Before
- Numeric values scaled *point size*, while lengths specified *additional gaps*.
** After
- =1.0=, =1.5= and =2.0= multiply the same *native single-spacing interval*.
** Changes
- Body lengths and invalid multipliers are *rejected before output*.
- Paragraph spacing remains an *additional length*.
** Unchanged
- Contents, copyright, font selection and configuration precedence remain separate.
** Edge cases
- Positive multipliers below one *compress spacing*; zero and non-finite values fail.
** Decisions
- Native Typst font metrics and its normal interline gap define *single spacing*.
** Next step
- Review the rendered comparison and record *user validation and closure*.

* Acceptance Criteria
:PROPERTIES:
:CUSTOM_ID: acceptance-criteria
:END:
** AC048.1 - Font-relative line intervals :ac:
:PROPERTIES:
:CUSTOM_ID: ac-048-1
:END:
- Body prose uses a *positive finite numeric multiplier* of the normal interval
  for the selected body font and size. =1.0= matches native single spacing;
  =1.5= and =2.0= scale it proportionally. Positive values below one are not clamped.
- Defaults remain *British 1.5* and *US 2*, with same-path overrides preserved.
- Verified by :: [[#rt-048-1][RT048.1 - Rendered multipliers]],
  [[#rt-048-4][RT048.4 - Preset defaults]] and
  [[#ut-048-1][UT048.1 - Visual spacing review]].
** AC048.2 - Independent paragraph gaps :ac:
:PROPERTIES:
:CUSTOM_ID: ac-048-2
:END:
- Paragraph spacing accepts *non-negative lengths* including =0.5em= and =5mm=.
  Zero adds *no extra gap*. Paragraph gaps do not change within-paragraph spacing.
- Verified by :: [[#rt-048-2][RT048.2 - Additive paragraph gaps]] and
  [[#ut-048-1][UT048.1 - Visual spacing review]].
** AC048.3 - Actionable invalid-value rejection :ac:
:PROPERTIES:
:CUSTOM_ID: ac-048-3
:END:
- Lengths, zero, negatives, empty or malformed strings and non-finite body
  multipliers *fail before writing Typst or PDF output*. The diagnostic identifies
  =folio.manuscript.line-spacing=, gives numeric examples and points to
  =paragraph-spacing= for lengths. Quoted numeric values remain accepted.
- Verified by :: [[#rt-048-3][RT048.3 - Invalid-value rejection]].

* Edge Cases
- *Compressed spacing* can overlap glyphs; positive values remain an explicit choice.
- Mixed-size inline objects can require taller lines; the multiplier defines
  *ordinary body prose*, not a constraint that clips larger content.
- Invalid paragraph lengths fail configuration validation; no Typst expressions
  are accepted as paragraph spacing.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:
- Configuration :: The existing loader validates and canonicalizes the numeric
  string before output. Paragraph gaps use the existing length validator.
- Rendering :: The existing body template restores Typst's native =cap-height=
  and =baseline= text edges. In the body font context it measures the line box
  and defines normal interval as *line-box height plus 0.65em*. Extra leading is
  =normal interval * multiplier - line-box height=. Paragraph spacing adds the
  configured gap to that leading. Frontmatter precedes this body-only wrapper.
- Verification :: The independent native Typst PDF reference has no custom
  line-height calculation; PDF coordinates establish the expected interval.
- Architecture :: Existing Go validation and file-backed Typst composition
  retain their responsibilities. *No new dependency* or persistent state.
- Security :: Configured body spacing is parsed as finite numeric data before
  template insertion; paragraph gaps are restricted to supported lengths.
  *No network, privilege or data-access change*.
