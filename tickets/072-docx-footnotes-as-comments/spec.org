* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- DOCX conversion turns supported attributed footnotes into *native Word comments by default* across all three public document commands.

** Before

- Attributed editorial notes remain footnotes and require a separate post-processing step.

** After

- A note beginning =[Name] wrote: ...= or =[Name] wrote (YYYY-MM-DD HH:MM:SSZ): ...= becomes a paragraph-anchored Word comment.
- Ordinary notes remain footnotes, and =--preserve-footnotes= retains *all* DOCX notes as footnotes.

** Changes

- =folio convert=, =folio manuscript= and =folio letter= accept =--preserve-footnotes= for DOCX output.
- The letter Org path gains the footnote-definition and reference support needed to apply the same DOCX rule.

** Unchanged

- PDF output is unchanged, and ODT conversion always retains native footnotes regardless of the flag.

** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:

- Multiple attributed notes may anchor to the same paragraph; existing comments and unrelated package parts remain intact.
- Invalid attributed timestamps or inconsistent references fail before an output is published.

** Decisions

- One bounded DOCX package transformation runs after native generation and before stdout or atomic publication; no external executable is invoked.

** Next step

- Definition review, then operator sign-off as described in [[#delivery-handoff][Delivery Handoff]].

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

Editorial feedback encoded as attributed Org footnotes currently becomes a document footnote. A separate tool can convert it to a Word comment, but First Folio does not perform that operation and therefore exposes different behaviour across its DOCX-producing commands.

** Outcome

Every DOCX command applies the same selective comment policy while preserving genuine footnotes and offering an explicit all-footnotes opt-out.

** Scope

*** In scope

- DOCX output from =folio convert=, =folio manuscript= and =folio letter=.
- Exactly two attribution forms at the start of the first footnote paragraph:
  - =[Name] wrote: comment text=
  - =[Name] wrote (YYYY-MM-DD HH:MM:SSZ): comment text=
- Multi-paragraph comment bodies, author, initials, comment date, paragraph anchoring and overlapping comments.
- =--preserve-footnotes= on all three commands.
- Org footnote parsing for letter bodies sufficient to produce native DOCX footnotes or comments.

*** Out of scope

- ODT comments; ODT footnotes remain footnotes.
- PDF annotations or changes to PDF rendering.
- Other attribution wording, inline comments, comment replies, resolved-state input or arbitrary timestamp formats.
- Converting an existing third-party DOCX file as a standalone command.

*** Unchanged

- Unattributed footnotes, source files, document layout and existing output-path safety rules.

** Authority and starting point

- Project profile :: [[file:../../.sdlc/project.yaml][=.sdlc/project.yaml=]]
- Product authority :: [[file:../../README.md][README]], [[file:../../docs/format-docx.md][DOCX format]] and [[file:../../docs/format-odt.md][ODT format]].
- Architecture authority :: [[file:../../docs/ARCHITECTURE.md][Project architecture]].
- Dependency :: [[file:../071-org-inline-and-footnote-parsing/spec.org][W071]] owns complete multi-paragraph Org footnote parsing and structured note output.
- Current implementation fact :: Script, manuscript and letter DOCX paths all produce bytes before publication, but their generation entry points differ; the letter model currently has no footnote-bearing body representation.

** Constraints and dependencies
:PROPERTIES:
:CUSTOM_ID: constraints-and-dependencies
:END:

- Deliver W071 first, or establish equivalent current structured-note evidence, before the end-to-end multi-paragraph cases can pass.
- Reuse First Folio's bounded package reader, XML model, validator and atomic publication flow where they preserve the required WordprocessingML.
- Add no runtime call to an external postprocessor and no Pandoc DOCX shortcut.
- Preserve the existing package expansion and XML limits; any new allocation is bounded by them.

** Decisions

- Only a complete match at the start of the first note paragraph is convertible; all other footnotes remain footnotes.
- The timestamp form accepts the exact UTC layout =YYYY-MM-DD HH:MM:SSZ=. Without a timestamp, the comment date is the conversion time in UTC, truncated to seconds.
- The comment author is =Name=, initials derive from its whitespace-separated words, and the attribution prefix is removed from comment text.
- The comment range covers the paragraph containing the original footnote reference.

** Unresolved blockers

- None.

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** Attribution near-misses

- Condition :: A note does not start with either exact attribution form, or =Name= is empty.
- Required behaviour :: It remains a footnote; substring matches and later-paragraph matches do not convert it.
- Covered by :: [[#ac-072-3][AC072.3 - Ordinary and explicitly preserved notes remain footnotes]] and [[#rt-072-1][RT072.1 - DOCX package conversion is selective and complete]].

** Invalid attributed timestamp

- Condition :: The timestamp form matches structurally but its value is not a valid exact UTC timestamp.
- Required behaviour :: Conversion fails before stdout or file publication; the note is not silently treated as ordinary.
- Covered by :: [[#ac-072-5][AC072.5 - Existing package content and publication safety are preserved]] and [[#at-072-2][AT072.2 - Invalid conversion is atomic]].

** Repeated reference

- Condition :: A convertible attributed footnote has zero or more than one document reference.
- Required behaviour :: Conversion fails rather than deleting shared content or creating an ambiguous comment range.
- Covered by :: [[#ac-072-5][AC072.5 - Existing package content and publication safety are preserved]] and [[#rt-072-1][RT072.1 - DOCX package conversion is selective and complete]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: The application and manuscript packages own CLI options and publication; native office writers own DOCX generation; =internal/office= owns bounded package and XML handling.
- Ownership boundary :: First Folio owns conversion of the DOCX bytes it generates; Word-compatible editors own interactive comment presentation.
- Existing pattern :: Every office path produces a complete byte slice before an atomic publisher or stdout writes it.

** High-level design

*** Components and responsibilities

- Add one =internal/office= DOCX comment transformer that accepts generated bytes plus a conversion policy and returns complete validated bytes or an error.
- Route the boolean =--preserve-footnotes= option through the three CLI models; invert it only at the shared transformer boundary.
- Extend the letter source/body model to collect referenced Org footnotes for native office projection while preserving the existing PDF path; only DOCX applies comment conversion.
- Keep attribution recognition and comment metadata construction inside the shared transformer so command paths cannot diverge.

*** Reuse, shared behaviour and variation

- Shared operation :: Package reading, candidate selection, relationship/content-type management, comment creation, identifier allocation and final validation execute once in =internal/office=.
- Variation :: Each command retains its own source and layout pipeline; the flag merely controls the common post-generation DOCX step.

*** Boundaries and dependencies

- The transformer consumes and returns bytes; it does not read or publish user paths.
- Use the repository's current bounded ZIP/XML infrastructure. A new XML dependency requires delivery-time evidence that the existing model cannot preserve required package content and renewed design approval.
- ODT and PDF paths must not call the transformer.

*** Flow

1. The command parses source footnotes, builds its native document and generates validated DOCX bytes.
2. Unless =--preserve-footnotes= is set, the shared transformer selects only exact attributed footnotes and replaces each single reference with a paragraph comment range/reference.
3. It updates footnotes, comments, extended comments, relationships and content types, validates the complete package and returns bytes.
4. The existing stdout or atomic publisher writes only the successful final bytes.

*** Essential mechanisms

- Match the first footnote paragraph against =^\[([^]\r\n]+)\] wrote(?: \(([^)]+)\))?: (.*)$= and reject an empty trimmed author.
- Parse explicit dates with the exact UTC layout; otherwise inject a controllable UTC clock value truncated to seconds.
- Preserve every comment paragraph after stripping attribution only from the first; generate initials from the first Unicode rune of each whitespace-separated author word.
- Allocate comment and paragraph identifiers above all identifiers already present. Retain existing comment parts and relationships when valid; add missing parts only when at least one note converts.
- Require exactly one document reference per convertible note. Remove only that note definition and reference run, retaining separator notes and every ordinary note.

*** Interfaces and configuration

- Interface :: =folio convert ... --preserve-footnotes=, =folio manuscript ... --preserve-footnotes= and =folio letter ... --preserve-footnotes=.
- Compatibility :: Omitting the flag changes only DOCX attributed-note handling. Existing invocations, ODT/PDF behaviour and ordinary DOCX footnotes remain compatible.

*** Data and state

- Generated DOCX gains or updates =word/comments.xml=, =word/commentsExtended.xml=, document relationships and content-type overrides only when a conversion occurs.
- Source files and persistent application state are unchanged.

*** Failure behaviour

- Invalid timestamps, malformed XML, unsafe or oversized package parts, relationship conflicts, exhausted identifiers and missing/duplicate references return contextual errors.
- Transformation and package validation finish before file replacement or any stdout write, preserving existing atomicity.

*** Simplicity and proportionality

- A single byte-level transformer reuses the common point already present in all three pipelines and avoids three comment writers or a process-level postprocessor dependency.

** Design decisions and verification

*** Transform generated DOCX once

- Decision :: Perform selective conversion after native DOCX generation and before publication.
- Rationale :: Comment mechanics are package-wide and independent of script, manuscript or letter layout.
- Verification :: [[#rt-072-1][RT072.1 - DOCX package conversion is selective and complete]] and [[#at-072-1][AT072.1 - All DOCX commands apply the same policy]].

*** Preserve footnotes by content rule and explicit flag

- Decision :: Exact attribution selects default conversion; =--preserve-footnotes= disables selection altogether.
- Verification :: [[#rt-072-1][RT072.1 - DOCX package conversion is selective and complete]], [[#at-072-1][AT072.1 - All DOCX commands apply the same policy]] and [[#ut-072-1][UT072.1 - Comments work in the document editor]].

*** Keep ODT native footnotes

- Decision :: Do not convert ODT notes to annotations or expose a separate ODT comment mode.
- Verification :: [[#rt-072-2][RT072.2 - ODT and PDF remain outside comment conversion]].

** Routine details left to implementation

- Internal function/type names and test-fixture builders may follow existing package conventions.

** Architecture impact

*** Security impact

- Threat boundary :: Unchanged; generated packages and source text remain bounded untrusted local data.
- Data and secrets :: Comment author, timestamp and text already exist in the source note and are copied only into the requested local DOCX; no new logging or transmission is introduced.
- Access :: No network or new process access. File publication remains under the existing target checks and atomic replacement boundary.
- Conclusion :: Apply existing ZIP part-name, expansion, XML-size and output atomicity controls to the transformer and reject conflicting package metadata.

*** Other relevant qualities

- Reliability :: A controllable clock makes no-timestamp metadata testable, while final validation and atomic publication prevent partial documents.
- Maintainability :: All commands share one exact attribution parser and WordprocessingML implementation.
