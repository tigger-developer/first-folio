* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

- Problem :: Org underline syntax renders as underline, but the editorial use case requires a visible highlighter treatment in PDF output.
- Scope :: Render Org =_marked_= text as pale yellow =#FFF59D= highlighting in PDF output from =folio convert=, =folio letter= and =folio manuscript=. DOCX and ODT are excluded from this emergency increment.
- Compatibility :: Markdown and Fountain underline remain underline. Org DOCX and ODT retain their current editable underline treatment.

* Emergency Delivery Record
:PROPERTIES:
:CUSTOM_ID: emergency-delivery-record
:END:

- TDD :: The public PDF regression first retained the marked text but detected no =#FFF59D= pixels in script, letter or manuscript output.
- Actual change :: Org-aware Typst projection now selects one shared highlight primitive. The manuscript Org-to-Markdown boundary canonicalizes Pandoc underline spans before applying the same projection.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

- Ownership :: =internal/typst= owns the shared highlight primitive. =internal/source= selects it for Org script and letter inline markup. =internal/manuscript= bridges Org's canonicalized underline span to it.
- Source boundary :: Selection depends on the recognized source format, not the output text alone, so Markdown and Fountain retain native underline.
- Office boundary :: Native DOCX and ODT renderers are unchanged and retain editable Org underline.
- Reliability :: The feature uses existing parsing and Typst compilation paths. It adds no dependency, network access, persistence or external state.
