* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- ODT conversion applies W073's *script title-page image contract* while keeping title metadata editable.

** Before

- Native ODT title pages contain text only and cannot represent configured background or inset artwork.

** After

- Background and inset images are *embedded in the ODT package* with proportional geometry.
- Overlay uses editable title text over localized blur and wash regions; inset-only dodge places editable metadata above and below the centred image.

** Changes

- The native ODT projection consumes the shared title-image plan and adds page-anchored ODF drawings and editable text regions.

** Unchanged

- The W073 YAML contract, source-relative path rule, non-title content, manuscripts, letters and no-image ODT route *remain unchanged*.

** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:

- Missing or invalid assets and unsupported combinations *fail atomically*; office-reader repair prompts are not acceptable output.

** Decisions

- ODT adds *no format-specific configuration* and does not rasterize title metadata into the image.

** Next step

- Definition review, then operator sign-off as described in [[#delivery-handoff][Delivery Handoff]].

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

PDF and DOCX adoption would leave ODT inconsistent with the public script title-image contract. Omitting artwork or flattening text would undermine ODT's role as an editable native output.

** Outcome

=folio convert= produces a self-contained ODT whose dedicated script title page follows W073 geometry and placement semantics and remains usable in an ODF-compatible editor.

** Scope

*** In scope

- Dedicated script title pages produced by =folio convert= to ODT.
- Background and inset modes, overlay and inset-only dodge placement, tone, opacity, blur, wash and equal-sided padding as defined by W073.
- Embedded PNG/JPEG package assets, page-relative positioning, cropping and editable title metadata.

*** Out of scope

- New YAML keys or altered W073 semantics.
- PDF, DOCX, manuscripts, letters, compact script titles and source-body images.
- Pixel-identical pagination or font metrics across ODF-compatible editors.

*** Unchanged

- The script parser, YAML cascade, image path base, later-page body content, native notes and existing no-image title-page output.

** Authority and starting point

- Project profile :: [[file:../../.sdlc/project.yaml][=.sdlc/project.yaml=]].
- Product authority :: [[file:../073-script-title-image-pdf/spec.org][W073 shared script title-image contract]] and [[file:../../docs/format-odt.md][ODT format contract]].
- Architecture authority :: [[file:../../docs/ARCHITECTURE.md][Project architecture]].
- Current implementation fact :: =internal/office= owns ODT package projection; =internal/office/odt_pages.go= and =internal/office/odt_layout.go= own script page and drawing layout.

** Constraints and dependencies
:PROPERTIES:
:CUSTOM_ID: constraints-and-dependencies
:END:

- W073's shared contract and plan and W074's completed cross-format lessons must be available before W075 implementation begins, preserving the requested PDF, DOCX, ODT sequence.
- The output must be self-contained and open without an external image path, network fetch, repair prompt or postprocessor.
- Title, subtitle, author, date and version remain editable text and use their configured typography.
- ODF-reader layout variation is permitted only within documented physical tolerances; mode, ordering, non-overlap and aspect ratio are not approximations.

** Decisions

- W075 consumes =folio.title-page.image= exactly as defined by W073 and introduces no ODT override.
- Background graphics are positioned relative to the physical page and behind text; insets are centred on the physical page with explicit physical extents. Overlay uses one editable primary region for title/subtitle/author and separate populated date and version regions, never full-width wash bands.
- Overlay and dodge use native editable text frames whose region geometry comes from the shared plan.

** Unresolved blockers

- None.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: W073 supplies the validated title-image plan and prepared image variants; the native ODT projection owns page styles, frames, drawings, pictures and manifest entries.
- Ownership boundary :: First Folio creates the complete ODF package. ODF-compatible editors own final layout and editing but must not be required to repair or fetch content.
- Existing pattern :: Extend the native ODT page/layout projection rather than adding an external converter or post-processing executable.

** High-level design

*** Components and responsibilities

- The application passes the same W073 plan and prepared assets used by prior formats into the ODT writer.
- The package layer embeds required image variants under =Pictures/=, registers manifest media types and allocates unique frame/image names.
- The title-page layout creates page-positioned image layers and editable text frames in the plan's order.

*** Reuse, shared behaviour and variation

- Shared operation :: Asset resolution, validation, proportional geometry, tone and region calculations remain W073 responsibilities.
- Variation :: ODT maps physical units directly to ODF lengths and uses drawing frames/text boxes while preserving shared semantics.

*** Boundaries and dependencies

- Add no new runtime process or network dependency. Use ODF constructs supported by the project's target editors.
- Prepared assets are package-local and referenced with internal =xlink:href= values only.

*** Flow

1. Public conversion loads W073 configuration and produces the shared plan.
2. The ODT writer embeds required image variants and constructs the title-page visual layer behind editable text frames.
3. Existing body and page-style generation follows, then the complete package is validated and atomically published.

*** Essential mechanisms

- A background frame is positioned at page origin behind content with page-sized extents and the plan's centred source crop.
- An inset frame uses explicit page-centred position and longest-axis extents.
- Overlay regions use positioned editable text boxes. Their background layer clips the aligned blurred image variant to the padded region, adds the tone wash at configured transparency, then places contrasting text above it.
- Dodge uses separate upper and lower editable text boxes around the page-centred inset. Region-relative =center= and =third= coordinates come from the shared plan rather than paragraph spacing heuristics.

*** Interfaces and configuration

- Interface :: No new public interface; consume W073's =folio.title-page.image= model.
- Compatibility :: The writer selects the image route only when the shared plan is present. Existing title paragraphs remain the no-image route.

*** Data and state

- Image parts are embedded below =Pictures/= with manifest entries and package-internal links. No external link or cache survives conversion.
- Source files and prepared temporary assets remain read-only and conversion-scoped.

*** Failure behaviour

- Missing assets, invalid plan geometry, duplicate identifiers, manifest mismatch or package validation failure abort before target replacement.
- Errors retain W073 field/path context where the failure originates and otherwise identify the ODT packaging boundary.

*** Simplicity and proportionality

- One native adapter reuses the existing ODT projection and W073 plan. It avoids a second configuration model, external postprocessor and rasterized title text.

** Design decisions and verification

*** Keep title metadata editable

- Decision :: Use native editable text boxes above image/treatment layers; do not bake metadata into PNG/JPEG assets.
- Verification :: [[#rt-075-1][RT075.1 - Native ODT package represents the shared image plan]] inspects text nodes and [[#ut-075-1][UT075.1 - ODT title images remain editable and stable]] verifies editing and round-trip behaviour.

*** Use page-positioned ODF frames

- Decision :: Position image and overlay frames against the physical page rather than flowing body paragraphs.
- Rationale :: Flow anchoring cannot reliably express full-page cover crop or region-relative dodge placement.
- Verification :: [[#at-075-1][AT075.1 - Public ODT conversion preserves title-image semantics]] measures rendered geometry and non-overlap.

** Routine details left to implementation

- ODF style names, frame names, picture filenames and manifest ordering may follow existing package conventions.
- The exact documented office-renderer tolerance is selected during RED test construction from current no-image layout tolerances; it may not excuse wrong mode, aspect ratio, order or overlap.

** Architecture impact

*** Security impact

- Threat boundary :: Unchanged from W073's local untrusted image input; ODT adds a ZIP/XML serialization boundary.
- Data and secrets :: Only requested image bytes and derived local variants are embedded. No source path or unrelated file content is added to the package.
- Access :: No additional file, process, network or privilege access beyond W073 asset loading and target publication.
- Conclusion :: Reuse W073 resource bounds, escape XML, allocate collision-free parts, validate manifest consistency and preserve atomic publication.

*** Other relevant qualities

- Interoperability :: Native, conforming ODF and editor round-trip validation are required; package-external links are excluded.
- Accessibility :: Metadata remains selectable text with contrast treatment; background artwork is decorative unless a later accessibility ticket adds alternative text policy.
- Maintainability :: The ODT adapter consumes shared geometry rather than recalculating policy.
