* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- *Org-mode scripts* converted to PDF or Typst render *inline emphasis with
  Org semantics*: =*bold*= is bold, =/italic/= is italic.

** Before

- The script renderer translated every single-asterisk span =*text*= to Typst
  italic, applying *Markdown* semantics to *Org* sources.
- Org authors writing =*this*= saw *italic* output where Org defines *bold*.

** After

- For *Org script sources*, =*text*= renders as *bold* and =/text*= renders as
  *italic* in Typst and PDF output.
- Markdown and Fountain script sources *retain their existing* inline-emphasis
  rendering.

** Changes

- The script Typst renderer receives the *source format* and selects the
  single-asterisk rule from it. See [[#solution-design][Solution Design]].

** Unchanged

- Markdown =*italic*= and =**bold**= rendering, Fountain handling, and every
  other inline rule (code spans, Org =/italic/=, underline, footnotes).
- Manuscript and letter rendering already follow Org emphasis semantics
  through their own parsers.

** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:

- Org =**text**= and =***text***= remain *bold* and *bold italic*: the
  double/triple-asterisk rules run *before* the single-asterisk rule.
- Emphasis inside *footnote definitions* follows the same source-format rules
  as the referencing text.
- Literal asterisks in Markdown and Fountain dialogue remain *unchanged*.

** Decisions

- No new automated regression test: the operator directs *user-test-only*
  validation for this bounded emergency fix, with the *maintained regression
  suite* re-run as the automated safety net. See [[#test-definitions][Test
  Definitions]].

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

- =folio convert play.org play.pdf= routed Org dialogue through an inline
  translator that treated =*text*= as Markdown italic, producing *italic*
  Typst output for Org *bold* text.

** Outcome

- Org script sources render inline emphasis according to *Org-mode markup
  rules* in Typst and PDF output.

** Scope

*** In scope

- Script (stage play / screenplay) conversion from *Org sources* to Typst and
  PDF, including footnote definitions and all event text that passes through
  the inline translator.
*** Out of scope

- Markdown and Fountain source behaviour; manuscript and letter rendering;
  text-format emitters; office (DOCX/ODT) export.
*** Unchanged

- Every inline rule other than the Org single-asterisk case, including Org
  =/italic/=, =_underline_=, ==code==, backtick code, and =**bold**= /
  =***bold italic***= handling.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: =internal/app/script_render.go= (inline translator
  and Typst renderer), =internal/app/convert.go= (format-aware entry point).
- Existing pattern :: The letter renderer already applies Org semantics to
  =*bold*= and =/italic/= in its own translator; manuscripts do so through
  Pandoc. The script renderer gains the same source awareness.

** High-level design

1. Thread =play.Format= from =runConvert= through =renderPlayDocument=,
   =renderPlayTypst=, =newScriptTemplateData= and =renderPlayBody= into
   =inlineTypst=.
2. In =inlineTypst=, keep every existing rule and its order. For the
   single-asterisk span, select the replacement by source format:
   - =play.FormatOrg= renders =*text*= as Typst =*text*= (bold).
   - All other formats keep the existing Typst =_text_= (italic).
3. Footnote recursion passes the same format through.

- Compatibility :: The renderer function signatures gain one parameter;
   the three internal test call sites (=script_running_test.go= twice,
   =script_title_test.go= once) pass =play.FormatOrg=.

** Security impact

- Threat boundary :: Unchanged; source text remains data translated to
  Typst content with the existing escaping and protect-token mechanism.
- Conclusion :: No security impact.
