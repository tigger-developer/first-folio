* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

- Problem :: A cover declared in source frontmatter cannot be suppressed by a shared profile, and disabling the title page rejects rather than ignores that cover.
- Scope :: Add =folio.cover-image.enabled= and make a disabled script title page suppress cover handling across PDF, DOCX and ODT. Active-cover behaviour remains unchanged.
- Authority :: Operator emergency requests on 2026-11-08; [[file:../../docs/config.md][configuration reference]] and [[file:../../docs/ARCHITECTURE.md][architecture]].

* Emergency Delivery Record
:PROPERTIES:
:CUSTOM_ID: emergency-delivery-record
:END:

- TDD :: Focused tests first observed an unknown-field error for =cover-image.enabled= and the existing title-page incompatibility error for all three formats.
- Actual change :: The typed cover resolver recognizes a strict Boolean switch and resolves either disable condition to no cover before active field and asset processing. Compact PDF composition groups a configured bottom-centre author because its dedicated metadata row is absent.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

- Ownership :: =internal/config= owns both early disable decisions and returns the existing zero-cover result. Renderers therefore require no separate switches.
- Cascade :: The new leaf is accepted from YAML and dotted Org source configuration. Recursive merging preserves a shared profile's false value when source frontmatter supplies the other cover fields but does not set =enabled=; an explicit source value retains normal source-over-local precedence.
- Validation :: If present, =enabled= must be Boolean. False bypasses active cover fields; true or omission retains strict current validation.
- Reliability :: Suppression occurs before image decode, Superscale, temporary variants and output-format compatibility checks. No network, dependency or persistence boundary changes.
