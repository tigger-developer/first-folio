* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- A dedicated *script title page* can contain a configured *background or inset image* in PDF output.

** Before

- Script PDF title pages contain text only and expose *no cover-image contract*.

** After

- A source-relative PNG or JPEG can *cover the page with proportional cropping* or appear as a *proportionally sized centred inset*.
- *Overlay* placement retains existing title-page text positions and can add a padded blur and light or dark wash behind each text region.
- Inset-only *dodge* placement puts title and subtitle above the centred image and author, date and version below it.

** Changes

- Top-level =folio.cover-image= defines a reusable cover asset, sizing, independent image and wash treatments, optional Superscale processing and placement; W073 makes script PDF its first consumer.
- A configured image counts as title-page content, so an image-only dedicated title page can be produced.

** Unchanged

- Compact first-page titles, manuscripts, letters, script body layout and title pages without an image *retain their existing behaviour*.

** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:

- Invalid combinations, unreadable assets and unsupported image data *fail before output publication* with a field-specific diagnostic.

** Decisions

- The PDF ticket owns the *shared configuration and renderer-neutral layout contract*; DOCX and ODT adoption are separate sequenced tickets.
- Inset =size= constrains the *longest image axis* and preserves aspect ratio; one =padding= length applies on all four sides of an overlay text region.

- Definition review, then operator sign-off as described in [[#delivery-handoff][Delivery Handoff]].

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

Script title pages cannot include cover artwork. Authors therefore cannot produce either a full-bleed visual cover or a centred letterbox-style illustration while retaining First Folio's configured title metadata.

** Outcome

=folio convert= produces a PDF whose dedicated script title page applies the configured image mode, proportional sizing and text relationship without changing later pages.

** Scope

*** In scope

- Dedicated script title pages produced by =folio convert= to PDF; the generated Typst remains an internal PDF-rendering intermediate when a cover is configured.
- Local PNG and JPEG image assets.
- Full-page background images with proportional cover cropping.
- Centred inset images sized on their longest axis.
- Overlay placement with optional blur and wash, and inset-only dodge placement.
- Optional local Superscale processing at its default scale or explicit =2x=, =4x= or =8x= before title-page composition.
- The shared script configuration, validation and source-relative path-resolution contract later consumed by W074 and W075.

*** Out of scope

- Manuscript and letter output.
- Compact script titles when =folio.title-page.enabled: false=.
- Source-body images, remote URLs, SVG, animated or multi-frame images, automatic subject detection and automatic treatment selection.
- DOCX rendering, owned by W074, and ODT rendering, owned by W075.
- Standalone =.typ= publication with a configured cover image; it requires an asset-publication contract outside W073.
- Arbitrary image editing beyond the crop, scale, image treatment, blur and wash required here.

*** Unchanged

- The existing YAML cascade, title metadata, per-role typography, running-matter suppression, body pagination and page-number semantics.
- A script with no =folio.cover-image.path= follows the pre-change title-page route byte-for-byte apart from unavoidable generator metadata.

** Constraints and dependencies
:PROPERTIES:
:CUSTOM_ID: constraints-and-dependencies
:END:

- The image path is resolved against the *source document's directory*, regardless of which YAML cascade layer supplied it.
- Title-image processing performs *no network access*. It invokes only the optional local =superscale= executable when explicitly configured and otherwise uses in-process image preparation.
- Delivery must preserve the existing no-image path and establish a reusable renderer-neutral configuration/layout model rather than embedding PDF-only semantics in configuration.
- W074 and W075 depend on the approved contract and shared model from this ticket; this ticket does not implement their output writers.

** Decisions

- The public YAML contract is top-level =folio.cover-image= so a later manuscript ticket can adopt it without migrating a script-owned path. W073 defines only script PDF consumption.
- The exact keys, defaults, accepted values and interactions are defined once under [[#cover-image-yaml-contract][Cover-image YAML contract]].
- Superscale is optional enhancement. A missing executable warns and falls back to the original image; a found executable that fails or returns invalid output causes atomic conversion failure.

** Unresolved blockers

- None.

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** Compact title mode

- Condition :: =folio.title-page.enabled= is =false= while an image path is configured.
- Required behaviour :: Conversion rejects the incompatible image configuration rather than placing an image in script body flow.
- Covered by :: [[#ac-073-6][AC073.6 - Image configuration resolves safely and consistently]] and [[#at-073-2][AT073.2 - Public conversion fails atomically for invalid image input]].

** Missing title text

- Condition :: A dedicated title page has an image but no title metadata.
- Required behaviour :: The image creates the page; absent text regions create no empty wash, blur or padding boxes.
- Covered by :: [[#ac-073-7][AC073.7 - Existing title-page behaviour remains compatible]] and [[#rt-073-2][RT073.2 - Typst output contains the resolved title-image layout]].

** Oversized inset

- Condition :: The requested longest-axis size exceeds the available title-page content area after required text regions and page boundaries.
- Required behaviour :: Conversion rejects =folio.cover-image.size= instead of clipping, distorting or overlapping content.
- Covered by :: [[#ac-073-6][AC073.6 - Image configuration resolves safely and consistently]] and [[#at-073-2][AT073.2 - Public conversion fails atomically for invalid image input]].

** Transparent pixels

- Condition :: A PNG contains transparency or =folio.cover-image.image.opacity= is below =100%=.
- Required behaviour :: The configured lightening or darkening image backing is visible through transparent image pixels and reduced image opacity within the image rectangle; transparency does not recolour page area outside an inset or expose uninitialized page content.
- Covered by :: [[#ac-073-3][AC073.3 - Overlay treatment preserves configured text placement]] and [[#at-073-1][AT073.1 - Rendered PDF geometry follows the image contract]].

** Superscale unavailable

- Condition :: Superscale is requested but cannot be found in inherited =PATH=.
- Required behaviour :: Conversion emits one bounded warning and completes with the original image without creating Superscale temporary output.
- Covered by :: [[#ac-073-9][AC073.9 - Unavailable Superscale falls back visibly]] and [[#rt-073-3][RT073.3 - Superscale invocation and fallback are deterministic]].

** Superscale execution or output failure

- Condition :: Superscale is found but exits unsuccessfully or does not create exactly one valid supported image.
- Required behaviour :: Conversion returns an operational error, publishes no target and removes its temporary output directory.
- Covered by :: [[#ac-073-10][AC073.10 - Superscale execution failures are atomic]], [[#rt-073-3][RT073.3 - Superscale invocation and fallback are deterministic]] and [[#at-073-2][AT073.2 - Public conversion fails atomically for invalid image input]].

** Consumer has not adopted cover images

- Condition :: =folio.cover-image.path= is present for standalone Typst, DOCX, ODT, manuscript or letter output before its corresponding adoption work is delivered.
- Required behaviour :: Conversion rejects the unsupported consumer before creating or replacing its target instead of silently omitting the cover.
- Covered by :: [[#ac-073-6][AC073.6 - Image configuration resolves safely and consistently]] and [[#at-073-2][AT073.2 - Public conversion fails atomically for invalid image input]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: The configuration package owns YAML cascade validation; the application script renderer owns source-path context and Typst data; =templates/script.typ= owns PDF page composition.
- Ownership boundary :: First Folio owns local asset loading, deterministic image planning and output. The PDF reader and Typst compiler render the resulting document but do not resolve application configuration.
- Existing pattern :: Extend the shared script title-page model and dedicated-page branch; do not add image semantics to manuscript title configuration or compact title flow.

** High-level design

*** Components and responsibilities

- Configuration validation parses =folio.cover-image= into a typed, renderer-neutral model and reports exact field errors.
- The application resolves =path= from the source document directory, validates image type and dimensions before output creation, and calculates physical background or inset geometry.
- A bounded image-preparation component optionally runs the configured Superscale command, validates the selected result, and provides normalized and blurred variants without changing the source asset.
- The Typst title-page template consumes the resolved plan, composes image layers and retains text as text above them.

*** Reuse, shared behaviour and variation

- Shared operation :: Path resolution, optional Superscale processing, decoding, proportional geometry, independent image/wash treatment, overlay treatment and dodge region calculation are represented once for W073-W075 and remain available for later manuscript adoption.
- Variation :: W073 projects the plan into Typst/PDF. W074 and W075 later map the same plan into their native package models.

*** Boundaries and dependencies

- Image bytes remain local, read-only input. Decoding must inspect dimensions before full allocation and enforce bounded decoded size to prevent unreasonable memory use.
- =superscale= is an optional runtime executable discovered only through the inherited =PATH= when =folio.cover-image.superscale= is non-null. First Folio neither installs it nor modifies =PATH=.
- A new Go image dependency is permitted only if delivery demonstrates that the standard library and existing Typst capability cannot meet required quality, and records its licence, maintenance and vulnerability evidence. No other runtime executable is permitted.

*** Flow

1. Load the normal script YAML cascade and validate the image block as a coherent unit.
2. Resolve the asset against the source document directory and inspect its type and dimensions within resource limits.
3. When requested, locate and invoke Superscale into a unique operating-system temporary directory; select its sole valid output or warn and retain the original asset.
4. Decode the selected asset, build the physical title-page plan, and prepare normalized and blurred variants only when required.
5. Pass the plan and assets to the Typst renderer, compose the dedicated title page, publish output atomically and retain the existing later-page route.

*** Essential mechanisms

- Background sizing uses =scale = max(pageWidth / imageWidth, pageHeight / imageHeight)= and centred clipping to the physical page rectangle.
- Inset sizing uses =scale = configuredSize / max(imageWidth, imageHeight)=; both rendered axes use that scale.
- Overlay treatment is clipped to each occupied text region expanded by the single configured padding. The region first shows the aligned blurred image layer when blur is non-zero, then the independently configured lightening or darkening wash, then contrasting live text.
- Dodge centres the inset on the physical title page and divides the content area at its rectangle. Title and subtitle form the upper group; author, date and version form the lower group. =folio.title-page.title.position= applies to both groups: =center= uses each available region's midpoint and =third= uses the point one third from its top. Existing horizontal alignment and date/version side settings remain applicable. Empty groups allocate no text box.

*** Interfaces and configuration

**** Cover-image YAML contract
:PROPERTIES:
:CUSTOM_ID: cover-image-yaml-contract
:END:

#+begin_src yaml
folio:
  cover-image:
    path: cover.jpg
    mode: inset             # background | inset
    placement: dodge        # overlay | dodge
    size: 80mm              # required for inset; longest rendered axis
    image:
      treatment: light      # light = lighten; dark = darken
      opacity: 100%         # original image opacity over that backing
    superscale: null        # null | default | "2x" | "4x" | "8x"
    overlay:
      blur: 0mm             # non-negative physical length
      wash:
        treatment: dark     # light = lighten; dark = darken
        opacity: 30%
      padding: 1em          # one em or mm length, applied on all sides
#+end_src

| Key | Accepted value | Default | Contract |
|-----+----------------+---------+----------|
| =path= | non-empty local PNG/JPEG path | none | Enables the cover image; relative paths use the source document directory. |
| =mode= | =background= or =inset= | none | Required with =path=. |
| =placement= | =overlay= or =dodge= | =overlay= | =dodge= is valid only with =inset=. |
| =size= | positive =mm= length | none | Required for =inset=, forbidden for =background=, and applied to the longest axis. |
| =image.treatment= | =light= or =dark= | =light= | Selects a white lightening or black darkening backing for the image rectangle. |
| =image.opacity= | =0%= through =100%= | =100%= | Original-image opacity over the selected image treatment. |
| =superscale= | null, =default=, =2x=, =4x= or =8x= | null | Null disables lookup; non-null requests one optional Superscale pass. |
| =overlay.blur= | non-negative =mm= length | =0mm= | Blur radius behind each overlay text region. |
| =overlay.wash.treatment= | =light= or =dark= | =light= | Selects a white lightening or black darkening wash independently of image treatment. |
| =overlay.wash.opacity= | =0%= through =100%= | =0%= | Opacity of the wash within each padded text region. |
| =overlay.padding= | non-negative =em= or =mm= length | =0em= | One value applied equally on all four sides. |

- Interface :: Top-level =folio.cover-image= is the sole public configuration added by W073. It is renderer-neutral and may be consumed by a separately defined manuscript change; this ticket consumes it only for a dedicated script PDF title page.
- Compatibility :: Absence of =path= selects the old route. Unknown children and invalid types fail under the existing configuration policy. W073 permits the block only for a dedicated script PDF title page; standalone Typst, DOCX, ODT, manuscript and letter consumers reject it until separately adopted. The block is invalid for compact script title mode. Non-default overlay treatment with =dodge= is invalid rather than ignored.
- Path contract :: Relative paths are joined to the directory of the file supplied as the conversion source, then cleaned. A relative path with stdin input fails because no source directory exists. The original source path is retained for diagnostics; image bytes are never written back.
- Image-treatment contract :: =image.treatment: light= composites the original image at =image.opacity= over white, so reducing opacity lightens it; =dark= composites over black, so reducing opacity darkens it. The backing occupies only the image rectangle: the whole page for =background= and the inset rectangle for =inset=. Dodge text and page area outside an inset retain their existing colours and background.
- Wash-treatment contract :: =overlay.wash.treatment: light= applies a white lightening wash and black overlay text; =dark= applies a black darkening wash and white overlay text. =overlay.wash.opacity= controls wash strength independently of =image.opacity=. The text colour follows wash treatment even at =0%= wash opacity; no automatic image analysis or inversion occurs.
- Sizing contract :: =background= uses proportional cover scaling and centred cropping to the configured physical page. =inset= scales the decoded image so its longest axis equals =size=: =200 x 400= at =80mm= becomes =40mm x 80mm=; =1000 x 250= at =50mm= becomes =50mm x 12.5mm=.
- Text-region contract :: Overlay has one primary region for the populated title/subtitle/author block and separate populated date and version regions at their existing positions; it never creates a full-width band. An =em= padding resolves against the largest configured font size among populated roles in that region.
- Dodge contract :: The inset is centred on the physical title page. The upper and lower regions are bounded by the title-page content margins and image rectangle. =folio.title-page.title.position= governs both: =center= uses each midpoint and =third= uses the point one third down from each region's top. Existing horizontal alignment and date/version side settings remain applicable.

**** Superscale process contract
:PROPERTIES:
:CUSTOM_ID: superscale-process-contract
:END:

- Discovery :: For a non-null value, resolve =superscale= with the inherited =PATH=. Do not probe, install, download or modify the environment when the value is null.
- Default invocation :: Run =superscale --no-face-enhance -o OUTPUT_DIR INPUT=. Omitting =--scale= deliberately delegates the scale level to Superscale; the inspected CLI currently defaults to =4x=.
- Explicit invocation :: =2x=, =4x= and =8x= add =--scale 2=, =--scale 4= or =--scale 8= respectively. Pass argv directly without a shell. Input is the resolved source image and output is a unique operating-system temporary directory.
- Face enhancement :: Always pass =--no-face-enhance=. The optional GFPGAN model changes content, has non-commercial licence components and may differ between machines; W073 requests upscaling only.
- Output :: On exit zero, require exactly one new regular PNG or JPEG output that passes the same dimension and decoded-resource validation as the source. Use that image for later normalization, blur and embedding while retaining the configured physical geometry.
- Unavailable fallback :: If lookup fails, emit one bounded stderr warning naming =folio.cover-image.superscale= and use the original image.
- Execution failure :: If a located process returns non-zero or its output is absent, ambiguous or invalid, return an operational error and publish no document. Include bounded diagnostic context without publishing Superscale stdout/stderr as document content.
- Side effects :: First Folio owns and removes its temporary output directory. Superscale may maintain its documented compiled CoreML model cache; First Folio neither clears nor manages that external cache.

*** Data and state

- Image and prepared variants exist only for the conversion lifetime and are not cached beside the source.
- Superscale output exists only in First Folio's unique temporary directory and is removed after success or fallback.
- The source image, YAML files and document metadata remain unchanged.

*** Failure behaviour

- Validate configuration before decoding, decode metadata before allocating full image storage, and complete preparation before replacing an output target.
- Errors name the full configuration field or resolved asset path without exposing unrelated file contents. Partial PDF, Typst or prepared-image output is not published.
- Superscale absence is a non-fatal warning with original-image fallback. Invalid configuration and execution/output failure are fatal before target publication.

*** Simplicity and proportionality

- One shared plan prevents three formats from inventing different semantics. Separate output tickets keep renderer-specific complexity and user validation bounded while the PDF ticket establishes the public contract first.

** Design decisions and verification

*** Preserve aspect ratio in both modes

- Decision :: Background uses proportional cover-and-crop; inset uses longest-axis sizing. Neither mode stretches axes independently.
- Verification :: [[#at-073-1][AT073.1 - Rendered PDF geometry follows the image contract]] measures both modes and the two explicit inset examples.

*** Keep overlay text live

- Decision :: Blur and wash affect image layers behind the text; title metadata remains renderer text rather than being rasterized into the cover image.
- Rationale :: This preserves searchable PDF text and gives W074/W075 a viable editable-text contract.
- Verification :: [[#rt-073-2][RT073.2 - Typst output contains the resolved title-image layout]] and [[#at-073-1][AT073.1 - Rendered PDF geometry follows the image contract]].

*** Use source-relative assets

- Decision :: Resolve every relative image path from the source document, not from the YAML file, current directory or installed preset.
- Verification :: [[#rt-073-1][RT073.1 - Cover-image configuration is validated and resolved]] uses distinct source, YAML and working directories.

*** Restrict dodge to inset mode

- Decision :: =background + dodge= is invalid because a full-page image leaves no image-free region to dodge.
- Verification :: [[#rt-073-1][RT073.1 - Cover-image configuration is validated and resolved]] and [[#at-073-2][AT073.2 - Public conversion fails atomically for invalid image input]].

*** Keep Superscale optional and deterministic

- Decision :: Superscale is enabled only by a non-null enum and uses direct argv with face enhancement disabled. Only lookup absence falls back with a warning; a found command's failure is an atomic operational error.
- Rationale :: First Folio remains portable when the macOS Apple-Silicon-only tool is absent, while preserving explicit failure when a requested and available processor does not produce the required asset.
- Verification :: [[#rt-073-3][RT073.3 - Superscale invocation and fallback are deterministic]] exercises the production lookup/runner boundary, argv, output selection, failure and cleanup; [[#ut-073-1][UT073.1 - Script title images are visually acceptable]] covers the installed command through public conversion.

** Routine details left to implementation

- Internal type and function names, prepared-image temporary filenames, bounded process-output capture and the exact anti-aliasing kernel may follow project conventions while preserving observable geometry, warnings and resource bounds.
- The delivery agent may select a safe decoded-pixel ceiling after inspecting existing resource policies, but it must be documented in the user-facing configuration reference and tested at its boundary.

** Architecture impact

*** Security impact

- Threat boundary :: A new untrusted local binary-image input crosses the conversion boundary.
- Data and secrets :: Image bytes remain local and are not transmitted. Superscale receives only the resolved image path and a unique temporary output directory; First Folio does not log image contents or embed process output.
- Access :: The converter reads the configured local asset and, only when requested, executes the =superscale= path found in the inherited =PATH= without a shell. Superscale may write its documented compiled model cache under the user's application-support directory.
- Conclusion :: Validate format and dimensions before full decode, bound decoded pixels, process output and temporary work, pass literal argv, disable optional face enhancement, clean First Folio temporary output, reject unsupported data, and preserve atomic publication.

*** Other relevant qualities

- Reliability :: Deterministic geometry and atomic failure prevent partial documents and format drift.
- Accessibility :: Wash treatment supplies its defined contrasting text colour independently of image treatment; user validation still checks real-world legibility because image content and wash strength vary.
- Portability :: The cover feature uses physical units and local embedded assets; output does not depend on the source image remaining available after conversion. Superscale enhancement degrades with a warning to the original image where its platform-specific executable is unavailable.
- Maintainability :: A shared plan and sequenced renderer adapters avoid three public contracts.
