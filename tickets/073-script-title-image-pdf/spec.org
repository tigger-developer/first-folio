* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:

** Outcome

- A dedicated *script title page* can contain a configured *background or inset image* in PDF output.

** Before

- Script PDF title pages contain text only and expose *no cover-image contract*.

** After

- A source-relative PNG or JPEG can *cover the page with proportional cropping* or appear as a *proportionally sized centred inset*.
- *Overlay* placement retains existing title-page text positions and can add a padded blur and light or dark wash behind each text region.
- Inset-only *dodge* placement puts title and subtitle above the centred image and author, date and version below it.

** Changes

- Top-level =folio.cover-image= defines a reusable cover asset, sizing, independent image and wash treatments, optional Superscale processing and placement; W073 makes script PDF its first consumer.
- A configured image counts as title-page content, so an image-only dedicated title page can be produced.

** Unchanged

- Compact first-page titles, manuscripts, letters, script body layout and title pages without an image *retain their existing behaviour*.

** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:

- Invalid combinations, unreadable assets and unsupported image data *fail before output publication* with a field-specific diagnostic.

** Decisions

- The PDF ticket owns the *shared configuration and renderer-neutral layout contract*; DOCX and ODT adoption are separate sequenced tickets.
- Inset =size= constrains the *longest image axis* and preserves aspect ratio; one =padding= length applies on all four sides of an overlay text region.

** Next step

- Definition review, then operator sign-off as described in [[#delivery-handoff][Delivery Handoff]].

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

Script title pages *cannot include cover artwork*. Authors therefore cannot produce a full-bleed or centred inset cover while *retaining configured title metadata*.

** Outcome

=folio convert= produces a PDF whose dedicated script title page applies *configured image mode, proportional sizing and text placement* while *leaving later pages unchanged*.

** Scope

*** In scope

- *Dedicated script PDF title pages*; generated Typst remains an internal intermediate when a cover is configured.
- *Local PNG and JPEG* assets.
- *Full-page proportional cover cropping*.
- *Centred longest-axis-sized insets*.
- *Overlay with blur/wash* and *inset-only dodge*.
- Optional local Superscale at *default, =2x=, =4x= or =8x=* before composition.
- A *shared validated source-relative contract* for later W074/W075 consumption.

*** Out of scope

- *Manuscript and letter* output.
- *Compact script titles* with =folio.title-page.enabled: false=.
- *Body images, remote URLs, SVG, animation and automatic treatment selection*.
- *DOCX and ODT rendering*, owned by W074 and W075.
- *Standalone configured-cover =.typ= publication*, which lacks an asset-publication contract.
- Image editing *beyond the specified crop, scale, treatment, blur and wash*.

*** Unchanged

- The *existing YAML cascade, metadata, typography, running matter, pagination and numbering*.
- Without =folio.cover-image.path=, the *pre-change title-page route remains unchanged* apart from unavoidable generator metadata.

** Authority and starting point

- Project profile :: [[file:../../.sdlc/project.yaml][*SDLC v3 project profile*]].
- Product authority :: [[file:../../docs/config.md][*Configuration and script title-page contract*]].
- Architecture authority :: [[file:../../docs/ARCHITECTURE.md][*Shared script composition and Typst/PDF route*]].
- Current implementation fact :: [[file:../../templates/script.typ][=templates/script.typ=]] *owns PDF title composition*; =internal/app/script_render.go= supplies validated data.
- Sequenced adoption :: *DOCX follows in W074; ODT follows in W075*.

** Constraints and dependencies
:PROPERTIES:
:CUSTOM_ID: constraints-and-dependencies
:END:

- The image path is *always source-document-relative*, regardless of the supplying YAML layer.
- Processing performs *no network access* and invokes only explicitly configured local Superscale.
- Delivery must *preserve the no-cover route* and establish a *renderer-neutral model*.
- W074/W075 *depend on this contract*; W073 does not implement their writers.

** Decisions

- The public contract is *top-level =folio.cover-image=* for later manuscript adoption; W073 defines *script PDF consumption only*.
- [[#cover-image-yaml-contract][Cover-image YAML contract]] owns the *exact keys, defaults, values and interactions*.
- Superscale is *optional and unbounded by accepted risk*; lookup, exit or output failure *warns and falls back to the original*.

** Unresolved blockers

- None.

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** Compact title mode

- Condition :: =folio.title-page.enabled= is =false= while an image path is configured.
- Required behaviour :: Conversion rejects the incompatible image configuration rather than placing an image in script body flow.
- Covered by :: [[#ac-073-11][AC073.11 - Invalid cover configuration fails atomically]] and [[#at-073-2][AT073.2 - Invalid and unsupported cover input fails atomically]].

** Missing title text

- Condition :: A dedicated title page has an image but no title metadata.
- Required behaviour :: The image creates the page; absent text regions create no empty wash, blur or padding boxes.
- Covered by :: [[#ac-073-13][AC073.13 - A cover can create an image-only title page]] and [[#rt-073-2][RT073.2 - Typst output contains the resolved title-image layout]].

** Oversized inset

- Condition :: The requested longest-axis size exceeds the available title-page content area after required text regions and page boundaries.
- Required behaviour :: Conversion *rejects the non-fitting image or measured text group* instead of clipping, distorting or overlapping content.
- Covered by :: [[#ac-073-11][AC073.11 - Invalid cover configuration fails atomically]], [[#ac-073-14][AC073.14 - Dodge rejects text-region overflow]] and [[#at-073-2][AT073.2 - Invalid and unsupported cover input fails atomically]].

** Transparent pixels

- Condition :: A PNG contains transparency or =folio.cover-image.image.opacity= is below =100%=.
- Required behaviour :: The configured lightening or darkening image backing is visible through transparent image pixels and reduced image opacity within the image rectangle; transparency does not recolour page area outside an inset or expose uninitialized page content.
- Covered by :: [[#ac-073-3][AC073.3 - Overlay treatment preserves configured text placement]] and [[#at-073-1][AT073.1 - Rendered PDF geometry follows the image contract]].

** Superscale unavailable

- Condition :: Superscale is requested but cannot be found in inherited =PATH=.
- Required behaviour :: Conversion *emits one warning and completes with the original image* without creating Superscale temporary output.
- Covered by :: [[#ac-073-9][AC073.9 - Disabled or unavailable Superscale is non-blocking]], [[#rt-073-3][RT073.3 - Superscale invocation and fallback are deterministic]] and [[#at-073-3][AT073.3 - Public Superscale fallback preserves PDF output]].

** Superscale execution or output failure

- Condition :: Superscale is found but exits unsuccessfully or does not create exactly one valid supported image.
- Required behaviour :: Conversion *emits one warning, removes temporary output and completes with the original image*.
- Covered by :: [[#ac-073-10][AC073.10 - Superscale execution failures fall back visibly]], [[#rt-073-3][RT073.3 - Superscale invocation and fallback are deterministic]] and [[#at-073-3][AT073.3 - Public Superscale fallback preserves PDF output]].

** Consumer has not adopted cover images

- Condition :: =folio.cover-image.path= is present for standalone Typst, DOCX, ODT, manuscript or letter output before its corresponding adoption work is delivered.
- Required behaviour :: Conversion rejects the unsupported consumer before creating or replacing its target instead of silently omitting the cover.
- Covered by :: [[#ac-073-12][AC073.12 - Unsupported consumers reject configured covers]] and [[#at-073-2][AT073.2 - Invalid and unsupported cover input fails atomically]].

** Source image exceeds a resource boundary

- Condition :: The original image is zero-dimensional or exceeds the configured-cover byte, per-axis or decoded-pixel limit.
- Required behaviour :: Conversion *reports the observed value and exact =folio.cover-image.path= limit before full decode* and leaves the target unchanged.
- Covered by :: [[#ac-073-15][AC073.15 - Source-image resource limits are enforced]], [[#rt-073-1][RT073.1 - Cover-image configuration, keys and source limits are validated]] and [[#at-073-2][AT073.2 - Invalid and unsupported cover input fails atomically]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: Configuration owns *cascade validation*; the application owns *source context and rendering data*; =templates/script.typ= owns *PDF composition*.
- Ownership boundary :: First Folio owns *asset loading, planning and output*; Typst renders but *does not resolve application configuration*.
- Existing pattern :: *Extend the shared script title model and dedicated-page branch* without changing manuscript configuration or compact flow.

** High-level design

*** Components and responsibilities

- Configuration validation *strictly validates only =folio.cover-image=* into a typed, renderer-neutral model and reports complete field paths; permissive unknown-key behaviour elsewhere remains unchanged.
- The application *resolves =path= from the source document*, enforces original-source byte/dimension/pixel limits before full decode, and calculates physical background or inset geometry.
- Image preparation *optionally invokes Superscale*, selects its output on usable zero exit, or warns and returns the original image for lookup, exit or output failure.
- The Typst title-page template *measures title groups with the actual configured fonts*, enforces dodge-region fit, composes image layers and retains metadata as live text.

*** Reuse, shared behaviour and variation

- Shared operation :: *Resolve, optionally upscale, decode, plan geometry/treatments and calculate regions once* for W073-W075 and later manuscript adoption.
- Variation :: W073 *projects into Typst/PDF*; W074/W075 later map the same plan into native packages.

*** Boundaries and dependencies

- Original image bytes remain *local, read-only and bounded before full decode*: file size at most =100MiB=, each axis from =1= through =32,768= pixels, and width times height at most =100,000,000= pixels.
- Superscale output is *explicitly exempt from First Folio byte, pixel, process-duration and process-output ceilings* under the recorded risk acceptance; it must still be one decodable PNG/JPEG with positive dimensions. Operating-system and decoder limits still apply.
- =superscale= is *optional and resolved only through inherited =PATH=* when configured. First Folio neither installs it nor modifies =PATH=.
- A new Go image dependency is permitted *only after evidence that existing capabilities cannot meet quality*, with licence/maintenance/vulnerability evidence. *No other runtime executable* is permitted.

*** Flow

1. Load the normal script YAML cascade and validate the image block as a coherent unit.
2. *Resolve and inspect the original asset* against the source document directory; reject source byte/dimension/pixel limits before full decode.
3. When requested, invoke Superscale into a unique operating-system temporary directory; *use one usable zero-exit output, otherwise warn and retain the original asset*.
4. Decode the selected asset, build the physical title-page plan, and prepare normalized/blurred variants only when required.
5. Pass the plan and assets to Typst, *measure overlay and dodge text groups*, compose the dedicated title page, and publish only a successful PDF.

*** Essential mechanisms

- Background sizing uses *proportional cover scale and centred page clipping*: =max(pageWidth / imageWidth, pageHeight / imageHeight)=.
- Inset sizing uses *one longest-axis scale for both axes*: =configuredSize / max(imageWidth, imageHeight)=.
- Overlay treatment is *clipped to each equally padded occupied text region*: aligned blur, independent wash, then contrasting live text.
- Dodge *centres the inset and divides the content rectangle at its image bounds*. Title/subtitle form the upper group; author/date/version form the lower group. =folio.title-page.title.position= applies within both regions; existing horizontal settings remain applicable.
- Typst constructs each populated group as a width-constrained block using the *actual font, stretch, spacing and prefix configuration*, then uses =measure= before placement. A height equal to its available region fits; any greater height raises a deterministic upper/lower-group error during compilation. The application maps that marker to a cover-layout diagnostic and *does not replace the target PDF*.

*** Interfaces and configuration

**** Cover-image YAML contract
:PROPERTIES:
:CUSTOM_ID: cover-image-yaml-contract
:END:

#+begin_src yaml
folio:
  cover-image:
    path: cover.jpg
    mode: inset             # background | inset
    placement: dodge        # overlay | dodge
    size: 80mm              # required for inset; longest rendered axis
    image:
      treatment: light      # light = lighten; dark = darken
      opacity: 100%         # original image opacity over that backing
    superscale: null        # null | default | "2x" | "4x" | "8x"
    overlay:
      blur: 0mm             # non-negative physical length
      wash:
        treatment: dark     # light = lighten; dark = darken
        opacity: 30%
      padding: 1em          # one em or mm length, applied on all sides
#+end_src

| Key | Accepted value | Default | Contract |
|-----+----------------+---------+----------|
| =path= | non-empty local PNG/JPEG path | none | Enables the cover image; relative paths use the source document directory. |
| =mode= | =background= or =inset= | none | Required with =path=. |
| =placement= | =overlay= or =dodge= | =overlay= | =dodge= is valid only with =inset=. |
| =size= | positive =mm= length | none | Required for =inset=, forbidden for =background=, and applied to the longest axis. |
| =image.treatment= | =light= or =dark= | =light= | Selects a white lightening or black darkening backing for the image rectangle. |
| =image.opacity= | =0%= through =100%= | =100%= | Original-image opacity over the selected image treatment. |
| =superscale= | null, =default=, =2x=, =4x= or =8x= | null | Null disables lookup; non-null requests one optional Superscale pass. |
| =overlay.blur= | non-negative =mm= length | =0mm= | Blur radius behind each overlay text region. |
| =overlay.wash.treatment= | =light= or =dark= | =light= | Selects a white lightening or black darkening wash independently of image treatment. |
| =overlay.wash.opacity= | =0%= through =100%= | =0%= | Opacity of the wash within each padded text region. |
| =overlay.padding= | non-negative =em= or =mm= length | =0em= | One value applied equally on all four sides. |

- Interface :: Top-level =folio.cover-image= is the *sole new public configuration*, renderer-neutral and consumed by W073 only for a *dedicated script PDF title page*.
- Compatibility :: Absence of =path= *selects the unchanged route*. W073 adds strict unknown-key rejection only within =folio.cover-image=; unknown keys elsewhere retain the existing permissive policy. W073 permits the block only for a dedicated script PDF title page; standalone Typst, DOCX, ODT, manuscript and letter consumers reject it until separately adopted. Compact title mode and non-default overlay treatment with =dodge= are invalid rather than ignored.
- Strict-key contract :: Allowed direct children are =path=, =mode=, =placement=, =size=, =image=, =superscale= and =overlay=. =image= allows only =treatment= and =opacity=; =overlay= allows only =blur=, =wash= and =padding=; =wash= allows only =treatment= and =opacity=. Any other child *fails with its complete path after cascade merge*.
- Path contract :: Relative paths are *resolved from the source document, never YAML/cwd*. Relative stdin input fails; source bytes are never modified.
- Image-treatment contract :: =light= *lightens over white* and =dark= *darkens over black* according to =image.opacity=, within the image rectangle only.
- Wash-treatment contract :: =light= gives *white wash/black text*; =dark= gives *black wash/white text*. Wash opacity is independent, and *no automatic inversion occurs*.
- Sizing contract :: Background uses *proportional cover crop*. Inset applies =size= to the *longest axis*: =200 x 400= at =80mm= becomes =40mm x 80mm=; =1000 x 250= at =50mm= becomes =50mm x 12.5mm=.
- Text-region contract :: Overlay uses *one populated title/subtitle/author region plus separate date/version regions*, never a full-width band. =em= resolves against the region's largest populated font.
- Dodge contract :: The inset is *physically centred*; upper/lower regions are bounded by margins and image. =center=/=third= apply *within each region*; horizontal settings remain applicable.

**** Source-image resource contract
:PROPERTIES:
:CUSTOM_ID: source-image-resource-contract
:END:

- Byte limit :: The original file must be *at most =100MiB= (=104,857,600= bytes)*. Check file metadata before reading the complete payload.
- Dimension limit :: Decode image configuration before pixel allocation. Width and height must each be *between =1= and =32,768=* and their checked product must be *at most =100,000,000=* pixels.
- Boundary :: Exact limits are valid. A zero dimension or one byte/pixel/axis unit above a limit *fails before full decode* with =folio.cover-image.path=, the observed value and the relevant limit.
- Superscale exception :: A generated Superscale result has *no First Folio byte, axis or pixel ceiling* under the accepted operational risk. It must still be exactly one regular, decodable PNG/JPEG with positive dimensions.
- Rationale :: The limits admit high-resolution print artwork while bounding an original decode to *100 million pixels, approximately =400MiB= for an RGBA buffer*, and reject pathological single-axis geometry before allocation. The Superscale exemption is the explicitly accepted exception.

**** Superscale process contract
:PROPERTIES:
:CUSTOM_ID: superscale-process-contract
:END:

- Discovery :: A non-null value *resolves Superscale from inherited =PATH=*; null performs no probe, install, download or environment change.
- Default invocation :: Run =superscale --no-face-enhance -o OUTPUT_DIR INPUT=; omitted =--scale= *delegates to the CLI default* (currently =4x=).
- Explicit invocation :: =2x=/=4x=/=8x= pass =--scale 2/4/8= as *literal argv without a shell*, using resolved input and a unique OS temporary directory.
- Face enhancement :: Always pass =--no-face-enhance= so W073 performs *upscaling only*, avoiding environment-dependent and non-commercial optional face processing.
- Output :: On exit zero, use exactly one new regular, decodable PNG/JPEG output with positive dimensions for later normalization, blur and embedding while retaining configured physical geometry. Zero usable outputs or multiple candidates are unusable success and follow fallback.
- Fallback :: Lookup absence, non-zero exit or unusable zero-exit output each *emit one stderr warning naming =folio.cover-image.superscale=* and use the original image. Process output is diagnostic only and never enters PDF/stdout content.
- Accepted process risk :: First Folio imposes *no process deadline and no stdout/stderr capture ceiling*. This deliberately accepts indefinite wait and unbounded diagnostic output from the trusted local utility. User/OS interruption remains available and triggers temporary-directory cleanup; revisit if Superscale reliability changes or a production incident demonstrates resource harm.
- Side effects :: First Folio *owns and removes its temporary output directory*. Superscale may maintain its documented CoreML cache, which First Folio does not manage.

*** Data and state

- Image and prepared variants *exist only for the conversion lifetime* and are not cached beside the source.
- Superscale output exists only in First Folio's unique temporary directory and is *removed after success, fallback or interruption*.
- The *source image, YAML and metadata remain unchanged*.

*** Failure behaviour

- *Validate strict keys, types and combinations before decoding*; enforce original-source metadata limits before allocating pixels; complete layout measurement and image preparation before replacing a target.
- Errors *name the full field, source limit or measured dodge group* without exposing unrelated contents. Partial PDF, Typst or prepared-image output is not published.
- Every Superscale lookup, exit and output failure is a *non-fatal warning with original-image fallback* under the accepted process risk.

*** Simplicity and proportionality

- *One shared plan prevents format drift*; separate output tickets bound renderer complexity while PDF establishes the contract first.

** Design decisions and verification

*** Preserve aspect ratio in both modes

- Decision :: Background uses *proportional cover-and-crop*; inset uses *longest-axis sizing*; neither stretches axes independently.
- Verification :: [[#at-073-1][AT073.1 - Rendered PDF geometry follows the image contract]] *measures both modes and both explicit inset examples*.

*** Keep overlay text live

- Decision :: Blur/wash affect *layers behind live title text*; metadata is not rasterized.
- Rationale :: This *preserves searchable PDF text* and an editable-text contract for W074/W075.
- Verification :: [[#rt-073-2][RT073.2 - Typst output contains the resolved title-image layout]] and [[#at-073-1][AT073.1 - Rendered PDF geometry follows the image contract]].

*** Use source-relative assets

- Decision :: Resolve every relative path *from the source document, not YAML/cwd/preset*.
- Verification :: [[#rt-073-1][RT073.1 - Cover-image configuration, keys and source limits are validated]] uses distinct source, YAML and working directories.

*** Restrict dodge to inset mode

- Decision :: *=background + dodge= is invalid* because a full-page image leaves no image-free region.
- Verification :: [[#rt-073-1][RT073.1 - Cover-image configuration, keys and source limits are validated]] and [[#at-073-2][AT073.2 - Invalid and unsupported cover input fails atomically]].

*** Keep cover-image keys strict and local

- Decision :: =folio.cover-image= and its nested mappings *reject every unknown child after cascade merge*; no other configuration namespace becomes strict.
- Rationale :: The block is new, so strict validation catches misspellings without breaking established permissive configuration elsewhere.
- Verification :: [[#rt-073-1][RT073.1 - Cover-image configuration, keys and source limits are validated]] covers unknown children at every block level and a permissive outside control.

*** Accept unbounded Superscale operation with fallback

- Decision :: Superscale uses *direct argv with face enhancement disabled*, but First Folio applies *no process deadline or process-output ceiling*. Lookup absence, non-zero and unusable output warn and fall back to the original image.
- Rationale :: The utility is treated as a well-tested trusted local enhancement. The accepted consequence is possible indefinite wait or unbounded diagnostic output; user interruption and cleanup remain required.
- Revisit trigger :: Reconsider limits after a Superscale reliability change, resource incident or evidence that interruption does not clean temporary output.
- Verification :: [[#rt-073-3][RT073.3 - Superscale invocation and fallback are deterministic]] verifies argv, results and cleanup; [[#at-073-3][AT073.3 - Public Superscale fallback preserves PDF output]] verifies public warnings/fallback; [[#ut-073-1][UT073.1 - Script title images are visually acceptable]] covers an installed utility.

** Routine details left to implementation

- Internal names, temporary filenames and anti-aliasing kernel may follow project conventions while *preserving geometry, warning and cleanup contracts*.

** Architecture impact

*** Security impact

- Threat boundary :: A *new untrusted local image* crosses the decode boundary; optional execution trusts the =superscale= binary found in inherited =PATH=.
- Data and secrets :: Image bytes *remain local and are not transmitted*. Superscale receives only the resolved path and unique output directory; process diagnostics never enter document content.
- Access :: The converter reads the configured asset and, only when requested, *executes Superscale without a shell*. Superscale may maintain its documented compiled-model cache.
- Conclusion :: Strictly validate the new block, *bound original source bytes/dimensions/pixels before full decode*, pass literal argv, disable face enhancement, clean temporary output and preserve atomic publication. Superscale duration, diagnostics and generated-image size remain explicitly unbounded under the accepted risk.

*** Other relevant qualities

- Reliability :: *Deterministic geometry and atomic publication* prevent partial documents and format drift.
- Accessibility :: Wash treatment supplies *defined contrasting text*; UT073.1 still checks real-image legibility.
- Portability :: Physical units and embedded assets make output *independent of the source after conversion*; missing platform-specific Superscale warns and falls back.
- Maintainability :: *One shared plan and sequenced adapters* avoid three public contracts.
