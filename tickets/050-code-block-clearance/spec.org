* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary

** Outcome
- Standalone code *retains normal paragraph separation* plus configured clearance.
** Before
- Code clearances *replaced paragraph separation*, compressing surrounding text.
** After
- Code blocks add clearance *above and below normal separation*.
** Changes
- Vertical =em= clearances use the *body font size*.
** Unchanged
- Inline code, code typography, indentation basis and source syntax *remain unchanged*.
** Edge cases
- Consecutive blocks and smaller monospace fonts *retain separation*.
** Decisions
- Complete-line code spans *keep their existing promotion* to code blocks.
** Next step
- Retain verification and review evidence for the *closure decision*.

* Edge Cases
- Smaller monospace text *must not erase surrounding separation*.
- Adjacent block margins retain Typst's existing collapse behaviour; this change
  does not sum two clearances at one shared boundary.
- Code indentation resolves *before changing the vertical-spacing context*,
  retaining its previous unit basis. No new indentation contract is introduced.
- Initial verification used objective PDF geometry and existing rendering
  regressions without requiring a UT. Explicit user validation is additionally
  retained in the closure record.

* Solution Design
** Rendering responsibility
- The existing =folio-code= helper owns the *shared code-block wrapper*.
  Raw block rendering delegates to it; inline raw rendering stays unchanged.
- Capture the existing indentation length before restoring the body font context.
  In that body context, each block side is *par.spacing plus configured clearance*.
  The configured monospace font and stretch still apply only to the content.
- This preserves the body multiplier and additional paragraph gap around code,
  and prevents raw's default font-size reduction from shrinking vertical =em=
  clearances. No parser, configuration loader or dependency changes are required.
- Review checks delegation, preserved indentation and unchanged inline handling;
  PDF geometry checks observable separation and clearance increments.
** Security impact
- Existing escaped content and validated configuration paths *remain unchanged*.
  No network calls, widened access, external writes or new interpretation of code
  content. Private manuscript material is excluded from retained tests.
