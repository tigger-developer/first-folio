## Original issue body

# Title-page item flushness: `#place(top+left)` items are slightly inset from the margins

## Problem

Under AC15.5 / AC15.12 (added in #15), title-page items placed with `#place(<compound-align>, float: true)` land at the correct corner but with a small consistent inset from the manuscript margin. The inset is 3-6mm depending on font size and appears on all six corner placements (title, subtitle, author, date, wordcount, version, contact).

The user's expectation for corner placement is "flush against the manuscript margin". The current implementation is close but not truly flush.

## Root cause

Typst's `#place(alignment, float: true)` aligns content by its content-box bounds. For text, the content box extends slightly beyond the visible glyph bounds by the font's ascent (above) and descent (below), plus any implicit leading. When Typst aligns content-box bottom to container bottom, the visible glyph baseline sits some number of points above the visual bottom edge.

For 10pt text this is around 2pt (~0.7mm) of extra space; for 20pt text it's around 4pt (~1.4mm). The visible effect is that all items sit slightly inside the manuscript margin rather than flush.

## Proposed fix

Compensate at the template level with per-item `dx` / `dy` adjustments derived from font size:

```typst
#place(
  top + right,
  float: true,
  dx: 0mm,
  dy: -0.15em  // pull text upward to visually align its top with the margin
)[...]
```

The compensation values need to be worked out per alignment (top → negative dy; bottom → positive dy; left/right → 0 dx). They may also vary by font family since ascent/descent ratios differ. A safe generic starting point:

- `top + *`: `dy: -0.15em`
- `bottom + *`: `dy: 0.15em`
- `* + left`: `dx: -0.05em`
- `* + right`: `dx: 0.05em`

These would apply to all `#place()` calls emitted for per-item title-page align.

## Out of scope

- Not this issue: the flushness of running header/footer text within the content area on body pages. That is a separate consideration (currently uses `align(right)` within a `pad`-less container and is generally close to the margin).

## Test plan

- Compile a manuscript with the AC15.12 defaults and use a PDF diff or measure to confirm each corner item touches (or is within 0.5mm of) the manuscript margin.
- Verify at both 10pt and 20pt font sizes.
- Verify no regression in centre-vertical placements (Typst `#place(center+left)` etc.) since those don't use `float: true` per AC15.5's floatable-only rule.
