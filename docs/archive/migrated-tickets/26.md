## Original issue body

## Problem

A British manuscript configured with a 13mm page margin places the title-page date only 5.91mm from the bottom edge. KDP rejects that date as outside its 6.4mm minimum printable boundary even though the remaining manuscript pages pass.

The title-page footer currently relies on Typst's implicit `footer-descent: 30%`. That default lowers the title-page version, word-count, and date grid into the bottom margin. Running-page headers and footers already use explicit geometry, so the title page behaves inconsistently.

Expected behaviour: title-page footer metadata uses explicit print-safe placement and does not inherit Typst's implicit footer descent.

## Reproduction

1. Configure a British 6x9 manuscript with `folio.manuscript.margin: 13mm`.
2. Enable the title page, date, and version.
3. Render the manuscript to PDF.
4. Inspect the first-page word bounding boxes or submit the PDF to KDP.

Observed on a 648pt-high page: the date glyph bounding box ends at 631.244729pt, leaving 16.755271pt or 5.91mm to the page edge.

## Violated acceptance criterion

- [AC9.8](https://github.com/tigger-developer/first-folio/blob/master/docs/ACs.md#issue-9-manuscript-pdf-mode): British manuscript output provides a publisher-friendly manuscript layout with configured margins and a title page.

## Solution

Set an explicit title-page footer descent in `templates/manuscript.typ` so the title-page metadata grid is not lowered by Typst's 30% default. Preserve the existing three-column version, word-count, and date layout and all per-item alignment overrides.

The verified candidate `footer-descent: 0pt` moves the date to 9.81mm from the page edge with the reported 13mm configuration, clearing KDP's 6.4mm minimum without changing the 413-page document count.
