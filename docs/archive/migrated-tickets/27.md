## Original issue body

## Problem

Typst's built-in outline entry rendering inserts an invisible `U+2060 WORD JOINER` immediately before every TOC page number. KDP reports these characters as non-printable characters at the beginning of part headings, although the PDF looks visually correct.

The full 413-page reproduction contains 51 word joiners in extracted TOC text. A minimal Typst reproduction confirms that `outline.entry.inner()` introduces the character; the manuscript part-bolding wrapper is not the cause.

Expected behaviour: manuscript TOC entries contain printable heading, leader, and page-number content without hidden word joiners rejected by print-production validation.

## Reproduction

1. Render a manuscript containing parts and chapters with the TOC enabled.
2. Extract the PDF text while preserving Unicode.
3. Inspect the bytes immediately before each TOC page number.

Observed: each entry contains UTF-8 `E2 81 A0`, representing `U+2060`, before the page number.

## Violated acceptance criterion

- [AC9.12](https://github.com/tigger-developer/first-folio/blob/master/docs/ACs.md#issue-9-manuscript-pdf-mode): manuscript TOC output includes configured part and chapter entries in document order.

## Solution

Replace the `outline.entry.inner()` rendering path with a custom linked entry assembled from Typst's documented `prefix()`, `body()`, `fill`, and `page()` components. Use a three-column grid and a fractional-width box for the dot leader. Preserve indentation, wrapping, links, dot leaders, page numbers, configured spacing, and bold part entries.

The verified full-manuscript candidate reduces extracted `U+2060` occurrences from 51 to zero while retaining all TOC rows and the 413-page document count.

### Revised diagnosis after KDP validation

The first correction removed every `U+2060`, but KDP continued to report non-printable markup on the two TOC pages. PDF object inspection found 52 `/Annot` objects across those pages, all with `/Subtype /Link` and internal section destinations. KDP is removing the clickable TOC links as non-printable markup.

The print-PDF solution must therefore omit the `link(...)` wrapper from custom TOC entries while preserving visible entry text, indentation, bold parts, dot leaders, page numbers, and the document outline generated from headings.
