## Original issue body

## Bug

Manuscript spacing configuration can generate invalid Typst or fail to affect visible TOC entry spacing.

- `folio.manuscript.line-spacing: 2em` is emitted as `2emem`, causing compilation to fail.
- `folio.manuscript.toc.line-spacing: 2em` changes paragraph leading inside an entry, but one-line TOC entries retain the hard-coded inter-entry gap and therefore do not render at the configured spacing.

## Existing acceptance criteria

- `AC9.13`: manuscript line spacing is configurable and explicit configuration overrides the active preset.
- `AC9.12`: manuscript TOC-specific layout overrides are applied when present.

## Root cause

`lineSpacingLeading` treats every non-numeric string as a unitless multiplier and appends `em`. The TOC template applies its setting to `par(leading:)` while inter-entry layout is independently fixed at `below: 0.5em`.

## Recommended correction

Normalize manuscript line spacing as either a numeric multiplier or a valid Typst length without duplicating units. Apply TOC spacing to the outline-entry layout so one-line entries visibly honour it while preserving wrapped-entry leading.
