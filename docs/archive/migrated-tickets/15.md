## Original issue body

# Manuscript config: additional page-layout fields and functionality

## Problem

The manuscript renderer already exposes a rich set of typography and layout controls, but publisher-grade manuscripts and book layouts require eight additional capabilities that are not currently supported. Together they close the remaining gaps between the current renderer and standard publisher expectations for header/footer content, page dimensions, blank-page insertion, per-item title-page placement, odd/even page-pair alignment, binding-side gutter, and publisher-ready defaults.

## Scope

Only manuscript rendering is affected. Script (British/US/screenplay) and letter renderers remain untouched, except that the custom `folio.page` `WxH` parsing under Feature 3 applies to any subcommand that reads `folio.page` if the change is trivially safe. That decision is documented in Solution.

## Features

### Feature 1 -- Additional page-header format placeholders

`folio.manuscript.page-header.format` currently substitutes `[author]`, `[title]`, and `[page]`. Publisher layouts also want the current part title (`[part]`) and current chapter title (`[chapter]`).

### Feature 2 -- `page-footer` block

A running footer, mirroring the fields, defaults, and inheritance of `page-header`, applied to manuscript body pages.

### Feature 3 -- Custom `page` dimensions

`folio.manuscript.page` currently accepts a named preset (`a4`, `letter`, `uk-book-b`, ...). It should also accept custom `WxH` dimensions in `mm` or `in` (for example `200x300mm`, `5.5x8.5in`).

### Feature 4 -- `blank-page-before` / `blank-page-after` on `part` and `chapter`

`page-break-before` is idempotent for sections that already start on a new page (contents, first chapter). Publisher layouts routinely require an intentional blank page adjacent to a part or chapter start. Adding `blank-page-before` and `blank-page-after` fields, independent of `page-break-before`, preserves the meaning of the existing field while enabling the layout.

### Feature 5 -- Compound alignment for title-page items

Individual title-page items (title, subtitle, author, date, word count, version, contact block) should each accept an `align` value that supports either a compass keyword (`left`, `center`, `right`) or a compound vertical-horizontal pair (`top-left`, `top-center`, `top-right`, `center-left`, `center-center`, `center-right`, `bottom-left`, `bottom-center`, `bottom-right`). Items are placed at the named corner flush to the manuscript margin.

### Feature 6 -- Book-layout compound alignment for header/footer

The manuscript is assumed to be a book layout where page 1 is a right-hand (odd) page, page 2 is a left-hand (even) page, and so on. `page-header.align` and `page-footer.align` should accept compound page-pair aliases (`left-right`, `right-left`, `left-center`, `right-center`, `center-left`, `center-right`) that place the first token's alignment on odd pages and the second token's alignment on even pages.

### Feature 7 -- Binding gutter

Bound books require extra inside margin (the "gutter") so printed content is not swallowed by the binding. `folio.manuscript.gutter` accepts a length value (default `0mm`) that is added to the inside (binding-side) margin on both odd and even pages using Typst's `inside`/`outside` margin idiom, which swaps sides automatically per page parity. A `0mm` gutter leaves rendered output byte-identical to the pre-gutter behaviour.

### Feature 8 -- Publisher-ready defaults for header and footer

The header/footer defaults are aligned with typical publisher expectations so a new project renders sensibly with no configuration:

- `page-header.format` defaults to `"[title] • [chapter] • [author]"` (was `"[author] / [title] / [page]"`).
- `page-header.align` defaults to `left-right` (was `right`).
- `page-footer.enabled` defaults to `true` (was omitted; had no default because the block did not exist).
- `page-footer.format` defaults to `"[page]"`.
- `page-footer.align` defaults to `center`.

# Solution Design

## Language, frameworks, libraries

- Go for configuration schema and orchestration (existing).
- `gopkg.in/yaml.v3` for YAML parsing (existing).
- `text/template` for Typst template expansion (existing, `internal/manuscript/render.go`).
- Typst for PDF rendering; no new runtime added.

No new dependencies are introduced.

## Files touched

| Path | Purpose |
|---|---|
| `internal/manuscript/config.go` | New schema fields; extend `normalizeConfig` defaults |
| `internal/manuscript/render.go` | Header/footer resolution; blank-page emission; align/page validation invocation |
| `internal/manuscript/pageformat.go` (new) | Parse and validate named vs. custom `WxH` page dimensions |
| `internal/manuscript/alignment.go` (new) | Parse and validate compass, compound `V-H`, and page-pair alignment values |
| `templates/manuscript.typ` | Emit footer, `state`-tracked part/chapter placeholders, per-item title-page placement, page-parity alignment, blank-page insertion, custom page dimensions |
| `internal/manuscript/manuscript_test.go` | Add RT-15.* regression tests |
| `docs/config.md` | Document new keys and their defaults |
| `examples/script.yaml.example` | Show representative uses (page-footer, blank pages, custom page, compound alignment) |

## Approach per feature

### Feature 1 -- `[part]` and `[chapter]` placeholders

- Introduce two Typst `state` values in the template: `folio-current-part` and `folio-current-chapter`, initialized to `""`.
- `#folio-part` and `#folio-chapter` update the corresponding state at heading time (chapter resets the state; a new part clears the chapter state until the next chapter).
- `renderHeader` (currently a static `strings.ReplaceAll` chain at `render.go:138`) becomes a template-time emitter that substitutes literal fields (`[author]`, `[title]`) statically and emits `#context state("folio-current-part").get()` / `#context state("folio-current-chapter").get()` for the dynamic tokens.
- Unknown bracket tokens (e.g. `[unknown]`) remain in the output as literal text.
- Empty part/chapter state renders as the empty string.

### Feature 2 -- `page-footer` block

- Add `PageFooterConfig` to `config.go` with fields identical to `PageHeaderConfig` (composition via a shared embedded struct is preferred to avoid drift).
- Extend `normalizeConfig` so `page-footer.*` inherits from `page-header.*` where unset, then from root `folio.*` per the documented inheritance model.
- Template: when `page-footer.enabled` is true, extend the running-page `#set page(...)` block with `footer: align(...)[#text(...)[<footer-content>]]` and set `footer-descent` to `content-padding-after`.
- Title-page and TOC pages already scope their own `#set page(footer: none)`; keep that unchanged so the running footer does not leak.

### Feature 3 -- Custom `WxH` page dimensions

- New `internal/manuscript/pageformat.go` with `parsePage(value string) (PageSpec, error)`.
- `PageSpec` is a small struct: `{ Named string; Width, Height string; Custom bool }` where `Width`/`Height` are Typst-safe length strings (e.g. `"200mm"`, `"5.5in"`).
- Regex: `^(\d+(?:\.\d+)?)x(\d+(?:\.\d+)?)(mm|in)$`. Both dimensions must share the unit; mixed units are rejected.
- Any other value with a hyphen/digit that is not a bare identifier is rejected with `"invalid page format: %q"`.
- Bare identifiers pass through as named presets and continue to be delegated to Typst's `paper:` argument.
- Template branches: `{{if .PageSpec.Custom}}#set page(width: {{.PageSpec.Width}}, height: {{.PageSpec.Height}}, ...){{else}}#set page(paper: "{{.PageSpec.Named}}", ...){{end}}`.
- Applied everywhere the manuscript template currently reads `folio.manuscript.page`.
- Extension to script/letter subcommands is deferred unless the same parser is reused without semantic change; if reused, script and letter tests are updated with the same accept/reject fixtures.

### Feature 4 -- `blank-page-before` / `blank-page-after`

- Add `BlankPageBefore`, `BlankPageAfter` `bool` fields to `HeadingConfig` (used by both `part` and `chapter`).
- Emission in the template: when the flag is set on a heading, emit a Typst block that renders one blank page. Idiom: a `#pagebreak(weak: true)` followed by a locally scoped `#set page(numbering: none, header: none, footer: none)` and an empty page body, then another `#pagebreak(weak: true)` back to the numbered running-page context.
- Weak pagebreaks avoid producing double blanks when combined with a heading that already opens a new page.
- Applied at the render.go emit step for `part` and `chapter` blocks: before/after the existing `#folio-part[...]` / `#folio-chapter[...]` call.

### Feature 5 -- Compound title-page item alignment

- Add per-item nested config structs to `TitlePageConfig`: `Title`, `Subtitle`, `Author`, `Date`, `WordCount`, `Version`, `Contact`, each with an `Align string` field (and later possibly `enabled`/typography, though this issue only touches `align`).
- Add `parseAlign(value string) (AlignSpec, error)` in `alignment.go`:
  - Bare `left|center|right` maps to horizontal-only (retains today's semantics).
  - Compound `V-H` where `V in {top,center,bottom}` and `H in {left,center,right}` maps to a Typst `V + H` pair.
  - Bare `center` in compound context becomes `center + center`.
  - Any other value returns a descriptive error naming the offending value.
- Template refactor: replace the current single `#align(center + horizon)[...]` block that stacks title/subtitle/author with independent `#place(align: <spec>, ...)` calls, one per item. `#place` combined with `dx`/`dy` set to `0` gives flush-margin placement because `#set page` already accounts for the margin.
- Backwards compatibility: if a per-item `align` is empty, fall back to legacy `title-block-align` for the title/subtitle/author group and to `footer-align` for the US grid footer, unchanged from today.
- Contact block: current template hardcodes `top + left`. Replace with `Contact.Align`, defaulting to `top-left` to preserve behaviour.

### Feature 6 -- Book-layout compound alignment for header/footer

- Extend `parseAlign` to accept the six page-pair aliases (`left-right`, `right-left`, `left-center`, `right-center`, `center-left`, `center-right`) as an `AlignPair` variant containing an odd and even horizontal alignment.
- Both the odd/even lookup at render time and the accept/reject validation live in the same parser to keep semantics in one place.
- Template: for `page-header.align` and `page-footer.align`, when the value parses as a page pair, emit `#align(if calc.odd(counter(page).at(here()).first()) { <odd> } else { <even> })[...]` inside a `#context` block. When the value is a scalar, keep the current `#align(<value>)[...]` shape.
- Page 1 is treated as odd (right-hand) per the requirement.
- Scalar values continue to be accepted uniformly on every page for backwards compatibility.

## Patterns to follow

- Follow the existing `normalizeConfig` `fill(&target, defaultValue)` pattern for new default values (`config.go:264`).
- Keep new schema fields alphabetized within their block for reviewability.
- Keep the Typst template file-backed (per AC10.7 in `docs/ACs.md` -- substantial layout must live in `templates/`, not embedded in Go string assembly).
- Reuse existing `escapeTypst` for any user-supplied string that reaches the template.
- Validate config at the load boundary (in `LoadConfig` / `normalizeConfig`), not at render time, so bad config surfaces with a clear file/line diagnostic before rendering starts.
- Prefer table-driven tests (`internal/manuscript/manuscript_test.go` already uses this shape) for parser accept/reject cases.

## Anti-patterns to avoid

- CODING.md §"Prohibited Anti-Patterns" -> §"Error Suppression": no `_ = err`, no swallowed YAML/parse errors. Wrap and return.
- CODING.md §"Input Validation": validate `page`, `align`, and `blank-page-*` values at the load boundary; do not defer to Typst compile-time errors, which give the user opaque messages.
- CODING.md §"Prohibited Anti-Patterns": do not embed complex generated Typst as heredocs or `fmt.Sprintf` strings in Go source. New template logic belongs in `templates/manuscript.typ` (AC10.7).
- TESTING.md §"The real-user test": RT-15.* assertions must exercise the manuscript CLI or the `RenderTypst` boundary and inspect generated Typst text or compiled PDF; do not grep the config struct or the source template to make a test pass.
- TESTING.md §"No mocks rule": no mocking of the config loader or the Typst renderer for these tests -- they exercise real config-to-Typst behaviour.
- CODING.md §"Readability First": one parser per concept (page format, alignment) -- do not sprinkle regex ad hoc across `render.go`.
