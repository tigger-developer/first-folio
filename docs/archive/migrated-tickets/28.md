## Original issue body

## Problem

The manuscript configuration accepts `folio.manuscript.copyright.isbn-barcode: file` and `render-and-file`, but the public `folio manuscript` command does not write the documented `<output-basename>.barcode.svg` sidecar. The manuscript help text also omits the external-barcode workflow.

## Violated acceptance criterion

Legacy [AC21.8](https://github.com/tigger-developer/first-folio/issues/21) requires `file` to write the SVG sidecar and `render-and-file` to write and embed it.

## Solution

Generate the EAN-13 SVG from the normalized copyright configuration after the primary manuscript artefact succeeds. Write it atomically beside the target using the target basename. Preserve the existing `none` and `render` behaviour. Document the configuration and command in the manuscript help and configuration reference.

## Regression tests

- ✅ RT-28.1: Public manuscript dispatch with `file` writes a valid SVG sidecar and does not embed SVG in the Typst target.
- ✅ RT-28.2: Public manuscript dispatch with `render-and-file` writes the sidecar and embeds SVG in the Typst target.
- ✅ RT-28.3: Manuscript help exposes the external SVG configuration, command, and resulting filename.
- ✅ RT-28.4: The documented PDF command writes the SVG beside a valid PDF.
