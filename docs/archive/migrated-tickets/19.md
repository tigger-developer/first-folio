## Original issue body

# Problem

`folio.manuscript.page-header.font-style` and `folio.manuscript.page-footer.font-style` do not affect the rendered header/footer typography. Users configure `font-style: italic` (or `oblique`) on the running header/footer and the setting has no visible effect.

Root cause: the `PageHeaderConfig` and `PageFooterConfig` structs in `internal/manuscript/config.go` do not declare a `FontStyle` field. `yaml.v3` silently drops unknown keys, so `font-style: italic` is parsed but discarded before it ever reaches the template. The template's `#text(...)` call for the header/footer emits `font`, `size`, and `weight` but no `style`.

This is asymmetric with title-page items (author, subtitle, etc.) which already accept `font-style` and apply it correctly.

# Reproduce

```yaml
folio:
  manuscript:
    page-header:
      font: Libertinus Sans
      font-size: 10pt
      font-weight: regular
      font-style: italic       # <-- silently ignored
      format: "[chapter]"
```

Render to `.typ` and inspect the emitted `header: context { ... #text(font: ..., size: ..., weight: ...)[...] }` — no `style:` argument is present, and the PDF renders in regular Libertinus Sans regardless of the configured `italic`.

# Regression coverage

- RT-B1: `page-header.font-style: italic` emits `style: \"italic\"` in the `#text(...)` call inside the `header: context { ... }` block of generated Typst.
- RT-B2: `page-header.font-style: oblique` emits `style: \"oblique\"`.
- RT-B3: `page-header.font-style: regular` (or empty) emits no `style:` argument (or omits it), preserving current rendering byte-for-byte.
- RT-B4: `page-footer.font-style: italic` emits `style: \"italic\"` in the footer `#text(...)` call.
- RT-B5: `page-footer.font-style` unset falls back to `page-header.font-style` (inheritance model, consistent with existing font/size/weight inheritance for `page-footer`).
- UT-B1: A human reviewer confirms a rendered manuscript with `page-header.font-style: italic` shows an italic running header in the PDF.

# Solution design

## Schema

Add `FontStyle string \`yaml:\"font-style\"\`` to both:
- `PageHeaderConfig` in `internal/manuscript/config.go`
- `PageFooterConfig` in the same file

## Normalization

In `normalizeConfig`, propagate `page-footer.font-style` from `page-header.font-style` when unset, matching the existing inheritance for `font`, `font-size`, and `font-weight`.

## Template

In `templates/manuscript.typ`, update the two `#text(...)` calls (one for header, one for footer) so that when `FontStyle` is non-empty a `style: \"{{.Config.Folio.Manuscript.PageHeader.FontStyle}}\"` argument is included. Guard with a Go-template `{{if}}` so an empty `FontStyle` emits nothing (preserving the existing byte-identical output for the unconfigured case).

## Documentation

Update `docs/config.md` under \"Page-header\" and \"Page-footer\" to list `font-style` alongside `font`, `font-size`, `font-weight`, with accepted values (`regular`, `italic`, `oblique`).

# Documentation impact

`docs/config.md` gains `font-style` entries for both `page-header` and `page-footer` blocks.

# Notes

Discovered while diagnosing a real manuscript configuration where the user set `font-style: italic` on `page-header`, expected italic running text, and saw no change. This bug also masked the diagnosis of a separate config-lookup issue (see companion issue for `script.yaml` walk-up lookup) because both symptoms looked like \"my config isn't taking effect\".
