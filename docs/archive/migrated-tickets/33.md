## Original issue body

## Problem

When `folio.manuscript.page-header.enabled` is `false`, a manuscript with a TOC and a non-zero gutter can retain the TOC top margin on subsequent body pages. The body-page `#set page` omits `top`, so Typst inherits `manuscript.margin + toc.continuation-padding-before` instead of falling back to `folio.manuscript.margin`.

Observed reproduction using the supplied project configuration:

- manuscript margin: `13mm`
- TOC continuation padding: British default `15mm`
- page header: disabled
- continuity-page first line: approximately `27.6mm` from the top edge

## Violated Acceptance Criteria

- **AC9.5:** manuscript settings inherit the root folio page and margin defaults unless overridden.
- **AC15.7 (legacy, issue #15):** a non-zero gutter changes only the inside horizontal margin; the zero-gutter layout preserves prior geometry.

## Solution

Emit an explicit body-page top margin whenever the running header is disabled:

- disabled header: `top: folio.manuscript.margin`
- enabled header: retain `distance-from-edge + content-padding-after`
- retain existing gutter `inside`/`outside` behaviour
- ensure disabled header distance and padding values cannot affect body geometry

## Regression Tests

- ✅ **RT-33.1:** With TOC continuation padding, non-zero gutter, and page header disabled, generated body-page Typst explicitly uses the manuscript margin for `top`.
- ✅ **RT-33.2:** Changing disabled-header distance and padding does not change generated body-page geometry.
- ✅ **RT-33.3:** Enabling the page header continues to use header distance plus content padding.
- ✅ **RT-33.4:** A compiled PDF places continuity text at approximately the configured manuscript top margin.

## User Test

- ⏳ **UT-33.1:** Render the supplied `manuscript.md` with its local `script.yaml`; continuity-page body text falls back to the configured `13mm` top margin when the header is disabled.
