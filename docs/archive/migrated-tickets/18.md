## Original issue body

## Problem

The manuscript parser currently treats an H1 as a "part" and an H2 as a "chapter", with the block's text set to the whole heading line as written in the source. Authors who want `PART 1: UNBELIEVED` as the rendered part heading must type `# PART ONE: UNBELIEVED` (or `# PART 1: UNBELIEVED`) into every part heading, and if they want to change the numbering style (arabic vs roman) or the prefix wording ("Part" vs "Chapter" vs a house-specific term), they must edit every heading in every file.

This has three consequences for the current manuscript-in-progress:

1. The part/chapter *numbering* is baked into the source. Changing "Chapter 1: Character" to "1. Character" or "I -- Character" requires a search-and-replace across all files.
2. The `[chapter]` and `[part]` header placeholders (added in #15) return the whole heading string ("Chapter 1: Character"), so a running header of `[page] * [chapter] * [author]` ends up as `12 * Chapter 1: Character * Alex Rowan`. The user prefers `12 * Character * Alex Rowan` -- semantic name only, no number noise.
3. There is no way to keep a stable semantic identity ("this chapter is 'Character'") separate from its presentation ("Chapter 1: Character" in the body but "Character" in the running head).

## Semantic authoring proposal

**Source** (author-facing):

```markdown
# Unbelieved

## Character

The hedges were higher than he remembered.
```

The H1 is the *part name*; the H2 is the *chapter name*. Nothing else in the heading line -- no prefix, no number, no separator, no colon. Numbering is derived from source order (H1s are numbered 1, 2, 3, ...; H2s reset per H1). File naming (`ch01.md`) is decoupled from rendered numbering.

**Config** (presentation):

```yaml
folio:
  manuscript:
    part:
      prefix: "PART "        # rendered before the number
      number-format: "1"     # "1" arabic | "I" roman-upper | "i" roman-lower
      separator: ": "        # rendered between the number and the name
      suffix: ""             # rendered after the name (rare)
      show-name: true        # whether the semantic name renders in the heading
      show-number: true      # whether the number renders in the heading
    chapter:
      prefix: "Chapter "
      number-format: "1"
      separator: ": "
      suffix: ""
      show-name: true
      show-number: true
```

**Rendered outcomes** for the demo source above with the config above:

- Part heading in body: `PART 1: Unbelieved`
- Chapter heading in body: `Chapter 1: Character`

Change `chapter.number-format` to `"I"` and every chapter re-renders as `Chapter I: Character` without touching source. Set `chapter.show-number: false, chapter.prefix: ""` to render just `Character` for chapters that should read as titled chapters ("Character", "The Watch", etc.) rather than numbered.

## Backward-compatibility

Existing manuscripts (like the user's current work-in-progress) that already write `# PART ONE: UNBELIEVED` or `# PART 1: UNBELIEVED` must continue to render sensibly without a mass source edit. The parser detects a leading `Part\s+(\w+|\d+|[IVXLCDM]+)([:.]?\s+)?` (case-insensitive) on H1 and a leading `Chapter\s+(\d+|[IVXLCDM]+)([:.]?\s+)?` on H2 and strips it, capturing:

- the *number* (arabic, roman, or spelled-out word),
- the *separator character* used in the source, and
- the *name remainder* after the separator.

The stripped semantic name is what's stored as the block's semantic identity. The auto-derived source-order number is preferred for rendering; a source-extracted number is used only when `part.explicit-numbering: source` is set (per-manuscript opt-in, in case a work has explicit non-sequential part numbers).

## Extended header/footer placeholders

The `[part]` and `[chapter]` placeholders (introduced in AC15.1) are amended so they return the *semantic name only*. Four new placeholders per level provide access to the other pieces:

| Placeholder | Returns |
|---|---|
| `[part]` | semantic name of the current part (e.g. `Unbelieved`) |
| `[part-number]` | current part's number in configured format (`1`, `I`, `i`) |
| `[part-prefix]` | configured part prefix (e.g. `PART `) |
| `[part-full]` | fully-rendered heading string (e.g. `PART 1: Unbelieved`) |
| `[chapter]` | semantic name of the current chapter (e.g. `Character`) |
| `[chapter-number]` | current chapter's number in configured format |
| `[chapter-prefix]` | configured chapter prefix |
| `[chapter-full]` | fully-rendered chapter heading |

The AC15.1 behaviour where `[chapter]` returned the whole heading text is preserved via `[chapter-full]`. A one-line migration note in `docs/config.md` calls out the change.

## Alt-format for facing-page layouts

Publishers commonly render different content on left (verso) vs right (recto) pages -- most often to keep the page number on the *outside* edge of the book. Under the current header/footer system a user must pick a single format that runs on both pages, forcing them to give up either the page number's outside placement or the content asymmetry.

Add `page-header.alt-format` and `page-footer.alt-format`. When defined, `format` is used on left (verso, even) pages and `alt-format` is used on right (recto, odd) pages. When `alt-format` is unset, `format` is used on every page (unchanged from today).

```yaml
folio:
  manuscript:
    page-header:
      format:     "[page] * [chapter] * [author]"   # left/verso pages: page number on the outer (left) edge
      alt-format: "[author] * [chapter] * [page]"   # right/recto pages: page number on the outer (right) edge
```

Combined with `align: left-right` (from AC15.6) or scalar `align: outside` (a natural future addition), a manuscript can put the page number on the outer edge on every page without a single line of Typst.

## Notes for reviewers

- **Pragmatic pivot**: the user is preparing a manuscript for a test print run today. AC18.2 backward-compat is deliberately generous so an existing `# PART ONE: UNBELIEVED` renders correctly under the new defaults with no source edit.
- **"Word-format" numbering (ONE, TWO)** is intentionally NOT in AC18.3's number-format list. Only arabic and roman variants are supported; spelling out numbers can come in a later ticket if genuinely needed.
- **Numbering is derived by default**. Manuscripts that need explicit numbering (e.g. Chapter 7 is called "Chapter 7" because the numbering is part of the fiction) can opt in with `explicit-numbering: source`.
- **AC18.4's semantic redefinition of `[chapter]`** is a breaking change relative to AC15.1. The migration is one line in the user's config: keep the AC15.1 behaviour with `format: "... [chapter-full] ..."` in place of `[chapter]`. A note goes in the AC15.1 documentation to point at this ticket for the semantic shift.
- **AC18.6 (alt-format)** deliberately does not introduce a "left/right/inside/outside" magic for `align`; it is simply two format strings picked by page parity. If a shorter idiom for the specific "page number on outer edge" pattern is wanted later (e.g. a scalar `align: outside`), that is a follow-up.
