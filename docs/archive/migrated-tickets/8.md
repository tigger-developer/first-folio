## Original issue body

## Problem

Fonts with multiple weight/stretch variants packaged under one family name (e.g. Asap, which includes Asap Condensed, Asap Expanded, and weights from Thin to Black) cannot be reliably selected with just \`folio.font: Asap\`. Typst's nearest-neighbour fallback picks an arbitrary variant — in practice this meant \`Asap\` resolved to Asap Condensed on a system where multiple stretch axes were installed.

Workaround attempts like \`font: Asap-Thin\` fail because Typst font names are *family* names, not full PostScript names — variants are selected via separate \`weight\` and \`stretch\` parameters.

## Solution

Add two optional config keys to both the script body and letter sections:

- \`font-weight\`: accepts Typst weight keywords (\`thin\`, \`light\`, \`regular\`, \`medium\`, \`bold\`, \`black\`) or numeric values 100–900
- \`font-stretch\`: accepts percentage (\`75%\`, \`100%\`, \`125%\`) or plain number (treated as percentage)

When provided, these are passed through to Typst's \`#set text(...)\` directive, pinning the exact variant.

### Example

\`\`\`yaml
folio:
  font: Asap
  font-weight: thin
  font-stretch: 100%

  letter:
    font: Asap
    font-weight: regular
    font-stretch: 100%
\`\`\`

## Post-merge bug-fix: case-normalise weight keyword

User test surfaced a Typst compile error when `font-weight: Thin` (capitalised) was used:

```
error: expected integer, "thin", "extralight", "light", "regular", "medium", "semibold", "bold", "extrabold", or "black"
```

Typst weight keywords are lowercase only. Fixed `_typst_weight` in `lib/Folio/CoverLetter.pm` and the inline equivalent in `lib/OrgPlay/TypstTemplate.pm` to lowercase any non-numeric weight value before quoting.

Numeric weights (e.g. `250`) pass through unchanged.

Will ship as v0.4.8.
