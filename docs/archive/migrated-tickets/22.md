## Original issue body

# Problem

When \`chapter.prefix\` (or \`part.prefix\`) is empty and \`chapter.separator\` is \`\". \"\` or \`\") \"\`, the composed heading body becomes \`1. Foo\`, \`2. Bar\`, \`1) Foo\`, etc. Passed to Typst as \`#heading(level: 2)[1. Foo]\`, the markup parser recognises \`<digit>+[.)] \` at position 0 as a numbered-list enum marker and reformats the entry as an enum item.

Symptoms:
- **TOC**: each entry renders across three visual lines: marker on line 1, chapter title on line 2, dot leader + page number on line 3.
- **Chapter opening pages**: the heading renders as an enum item rather than a normal heading.
- **Running header** using \`[chapter-full]\`: unaffected (state-stored string is inserted verbatim, not re-parsed as markup) — but this needs confirmation in the RT.

Reproduced with a user's real manuscript: \`chapter.prefix: \"\"\`, \`chapter.separator: \". \"\`, \`chapter.number-format: \"1\"\`. Switching separator to \`\": \"\` restores normal rendering. The trigger is the space after the punctuation — without it (\`1.Foo\`) Typst does not recognise the enum marker.

# Regression coverage

- RT-22.1: chapter with \`prefix: \"\"\`, \`separator: \". \"\`, name \`Foo\` emits \`#folio-chapter(...)[1\\. Foo]\` in generated Typst (backslash before the dot).
- RT-22.2: chapter with \`prefix: \"\"\`, \`separator: \") \"\`, name \`Foo\` emits \`#folio-chapter(...)[1\\) Foo]\`.
- RT-22.3: chapter with \`prefix: \"Chapter \"\`, \`separator: \". \"\` emits \`#folio-chapter(...)[Chapter 1. Foo]\` unchanged (no enum trigger because body does not start with a digit).
- RT-22.4: chapter with no number shown emits \`#folio-chapter(...)[Foo]\` unchanged.
- RT-22.5: the \`full: %q\` argument (state-storage form) is NOT escaped (\`full: \"1. Foo\"\`, not \`full: \"1\\\\. Foo\"\`), because state values are inserted as strings and not re-parsed as markup.
- RT-22.6: same escape applied to part emit sites (\`part.prefix: \"\"\` + \`part.separator: \". \"\` triggers the same bug on part pages).
- UT-22.1: reviewer confirms a real manuscript with \`chapter.prefix: \"\"\` + \`chapter.separator: \". \"\` renders the TOC with each entry on a single line and the page number on the same line as the title.

# Solution design

## Escape at emit time

In \`internal/manuscript/render.go\`, add a helper:

\`\`\`go
var typstEnumPrefixRE = regexp.MustCompile(\`^(\d+)([.)])( )\`)

// escapeTypstEnumPrefix prevents Typst's markup parser from interpreting a heading
// body that starts with \`<digit>+[.)] \` as an enum item.
func escapeTypstEnumPrefix(s string) string {
    return typstEnumPrefixRE.ReplaceAllString(s, \`${1}\\\\${2}${3}\`)
}
\`\`\`

Apply the escape to the body argument of \`#folio-chapter(...)[body]\` and \`#folio-part(...)[body]\` at their Sprintf sites in \`renderBlocks\`. Do NOT apply the escape to the \`full: %q\` argument (state-storage), because state values are inserted as strings and rendering a literal backslash would be visible in the running header/footer.

## Backwards compatibility

Composed headings that do not start with the enum pattern (e.g. \`Chapter 1. Foo\`, \`Part I: Foo\`, \`Foo\`, \`1st chapter\` — no space after digit) are unaffected. The escape is a no-op for the vast majority of configs.

# Documentation impact

None. This is a rendering correctness fix; the config surface does not change.
