## Original issue body

# Frontmatter-format for page-header and page-footer

## Problem

Publisher-grade manuscripts frequently need a different running header/footer on frontmatter pages (title, copyright, TOC, dedication, epigraph) than on body pages. Today \`page-header.format\` and \`page-footer.format\` apply uniformly to every page, so the only way to suppress the header on the copyright page is to set \`copyright.skip-header: true\` -- a per-block escape hatch that doesn't generalise to title, TOC, or future frontmatter blocks and duplicates state (each block needs its own suppress flag).

Extend the existing \`format\` / \`alt-format\` grammar with \`frontmatter-format\` / \`alt-frontmatter-format\` so a single header/footer configuration controls both regions.

## Scope

Only manuscript rendering is affected. Script and letter renderers untouched.

The feature slots into the existing \`page-header\` and \`page-footer\` schema and the existing \`format\` / \`alt-format\` grammar (issue #15 AC15.1, issue #18 AC18.6). It reuses the frontmatter-vs-body boundary state that the BYPASS-GATE-7 offset work seeded at the first body block.

## Frontmatter definition

A page is **frontmatter** if it renders before the first body block (part or chapter). Everything from the first body block onward is **body**. Matches Chicago Manual and general publishing convention.

The boundary is already marked in the emit: the offset-state seeded by the first \`#folio-part\` / \`#folio-chapter\` (from the BYPASS-GATE-7 physical/display counter split during issue #15). This ticket adds a companion \`folio-is-body\` bool state so the header/footer context can distinguish the two regions per-page.

## Grammar

For each of \`page-header\` and \`page-footer\`:

| \`format\` | \`alt-format\` | \`frontmatter-format\` | \`alt-frontmatter-format\` | Behaviour |
|---|---|---|---|---|
| set | unset | unset (\`nil\`) | unset (\`nil\`) | \`format\` on every page (current behaviour, unchanged) |
| set | set | unset (\`nil\`) | unset (\`nil\`) | \`format\` on verso, \`alt-format\` on recto, every page (current behaviour, unchanged) |
| set | any | set (non-empty) | unset (\`nil\`) | body pages as above; frontmatter uses \`frontmatter-format\` on every frontmatter page |
| set | any | set (non-empty) | set (non-empty) | body pages as above; frontmatter uses verso/recto pair (\`frontmatter-format\` on verso frontmatter, \`alt-frontmatter-format\` on recto frontmatter) |
| set | any | set (\`\"\"\` empty string) | any | frontmatter pages render blank header/footer |

\"Unset (\`nil\`)\" means the YAML key is absent from the local config. \"Set (empty string)\" means the key is present with value \`\"\"\`. To distinguish these two states in Go we use \`*string\` fields.

## Config shape

```yaml
folio:
  manuscript:
    page-header:
      enabled: true
      format: \"[title] • [chapter] • [author]\"
      alt-format: \"[chapter] • [page]\"       # existing (issue #18)
      frontmatter-format: \"\"                   # new: blank on frontmatter
      alt-frontmatter-format: null              # new: unset -> falls back to frontmatter-format
      # ... existing font/size/align/etc.

    page-footer:
      enabled: true
      format: \"[page]\"
      frontmatter-format: \"[page]\"             # explicit; falls back to format if omitted
      alt-frontmatter-format: null
```
