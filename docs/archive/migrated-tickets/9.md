## Original issue body

## Problem

First Folio can render stage-play source files to PDF, but prose manuscript submission still depends on external word processors. Re-rendering a novel manuscript through Word or LibreOffice creates repeated formatting friction and makes print/PDF output harder to reproduce.

The CLI needs a manuscript mode that can collect chapter Markdown files from a project tree such as `~/notes/about-time-nove/part?/ch??.md` and render a submission-ready PDF such as `~/creative/subs/obrien-about-time/04-manuscript-ch1-3.pdf`.

## Requirements

- Add a manuscript-oriented CLI mode for prose Markdown and org-mode chapter sources.
- Exclude Fountain from manuscript compatibility. Fountain remains a script/screenplay format, not a prose manuscript source format.
- Define manuscript source contracts that rhyme with the existing stage-play Markdown and org-mode contracts: front matter, headings, body paragraphs, scene breaks, footnotes, and private notes have explicit syntax.
- Base manuscript configuration on the existing `british-script.yaml`/`script.yaml` design and preserve backward compatibility with existing `folio.font`, `folio.font-size`, `folio.page`, `folio.margin`, `folio.title-page.*`, and `folio.letter.*` settings.
- Add root `folio.heading-font` and `folio.heading-font-size` defaults. When omitted, heading font values inherit from `folio.font` and `folio.font-size`.
- Treat mode-level and child font settings as overrides of the root defaults, not as separate required configuration families.
- Add British and US manuscript presets. British manuscript remains the default; US manuscript is an override preset, following the script preset model.
- Include a generated table of contents by default, with boolean config to disable it and TOC-specific font/layout overrides.
- Keep A4 as the default page size for every rendering mode. `us-letter` is configurable, but no preset or mode silently makes it the default.
- Accept one or more shell-expanded input paths or a quoted glob pattern for chapter selection.
- Preserve chapter order using the resolved path order after deterministic sorting.
- Concatenate multiple input files with an inserted blank-line separator so the last line of one file cannot run into the first heading or paragraph of the next file.
- Render a single PDF by default, with Typst source available through a `.typ` output path.
- Fail clearly for missing inputs, empty matches, unsupported input formats, and unwritable output paths.

## Existing Config Foundation

The current canonical preset starts from this model and must remain the foundation:

```yaml
folio:
  font: Libertinus Serif
  font-size: 12pt
  # font-weight and font-stretch are optional. Useful for fonts whose
  # family name groups multiple variants (e.g. Asap bundles Asap Condensed
  # and Asap Expanded under "Asap"). Without these, Typst may select a
  # nearest-neighbour variant instead of the regular one.
  # font-weight: regular   # thin, light, regular, medium, bold, black, or 100-900
  # font-stretch: 100%     # 75%, 100%, 125% — pins the stretch axis
  page: a4
  margin: 25mm
  default-format: pdf
```

The issue adds root heading defaults, not replacement root body defaults:

```yaml
folio:
  heading-font: Libertinus Serif
  heading-font-size: 14pt
  # heading-font-weight: bold
  # heading-font-stretch: 100%
```

`folio.heading-font` inherits from `folio.font` when omitted. `folio.heading-font-size` inherits from `folio.font-size` when omitted. Existing `folio.font`, `folio.font-size`, `folio.font-weight`, and `folio.font-stretch` remain the default body-text contract.

The current `folio.letter.font` and `folio.letter.font-size` pattern is the mode override model to follow for manuscript.

## Manuscript Config Contract

### Root and mode inheritance

Mode and child font keys are overrides. The inheritance model is:

1. Child element override, such as `folio.manuscript.title-font`
2. Manuscript mode override, such as `folio.manuscript.font`
3. Root default, such as `folio.font`
4. Built-in default from the active preset

For headings:

1. Child heading override, such as `folio.manuscript.chapter.heading-font`
2. Manuscript mode override, such as `folio.manuscript.heading-font`
3. Root heading default, such as `folio.heading-font`
4. Root body default, such as `folio.font`
5. Built-in default from the active preset

### Manuscript keys

## Manuscript Presets

### Preset file layering

Manuscript presets must follow the same deep-merge model as script presets:

1. Load the British manuscript preset as the base manuscript configuration.
2. If manuscript style is `us` or `american`, deep-merge the US manuscript override file on top of the British base.
3. Deep-merge global `script.yaml`, global style-specific user config, local `script.yaml`, local style-specific user config, and CLI flags above the presets using the existing precedence model.

The US manuscript file is not a complete independent config. It is a small override file that declares only the values that differ from British manuscript defaults.

### British manuscript preset

Add `presets/british-manuscript.yaml`. British manuscript is the default manuscript base, consistent with the existing British script default.

British defaults:

- Page: inherit root `folio.page`, built-in default `a4`.
- Body font: inherit root `folio.font`, built-in default `Libertinus Serif`; body prose is the only British manuscript element that defaults to Libertinus Serif.
- Heading family: title, author, metadata, part headings, chapter headings, running header, TOC heading, and TOC entries default to `Libertinus Sans` with element-specific size, weight, and style.
- Heading font: British manuscript headings default to `Libertinus Sans`, with root/user overrides still taking precedence.
- Margins: 20mm on all sides for A4 British manuscript output.
- Title page: includes title, subtitle, author attribution, author, date, word count, address, email, website, and version when present.
- Running header: `[author full name] / [book title] / [page number]` at the top right, 20mm from the page edge.
- Header spacing: title/body content begins below the running header with `folio.manuscript.page-header.content-padding-after`, default `10mm`.
- Table of contents: enabled by default after the title page; includes parts and chapters in document order.
- Parts: a part heading such as `PART ONE` is rendered on its own page, centred vertically and horizontally.
- Chapters: each chapter starts on a new page about one third down the page; body text starts on the same page below the chapter title.

The British base YAML should be explicit enough to document the defaults, while still inheriting root values where appropriate:

### US manuscript preset

Add `presets/us-overrides-manuscript.yaml`. US manuscript is opt-in and follows a Shunn-based manuscript layout by deep-merging this file on top of `presets/british-manuscript.yaml`.

US defaults:

- Page: inherit root `folio.page`; `us-letter` is available only through explicit user config.
- Body font: monospaced manuscript font, default `Libertinus Mono`.
- Mono font: `Libertinus Mono`.
- Text size: 12pt.
- Margins: Shunn-style manuscript margins expressed in metric units, configurable through `folio.manuscript.margin`.
- Paragraph layout: Shunn-style double spacing, 12.7mm first-line indentation, and zero paragraph spacing by default.
- Title page: includes title, subtitle, author attribution, author, date, word count, address, email, website, and version when present.
- Running header: shared `[author full name] / [book title] / [page number]` top-right format.
- Table of contents: inherited from the British base unless overridden.
- Page numbering: no visible number on title page; text page numbering starts at 1.
- Chapters: each chapter starts on its own page.

## Manuscript Source Contracts

The manuscript contracts should be documented beside the existing format contracts, either as new `docs/format-manuscript-markdown.md` and `docs/format-manuscript-org.md` files or as clearly separated manuscript sections in the existing format docs. They should be written in the same element-schema style as `docs/format-markdown.md` and `docs/format-org.md`.

### Markdown Manuscript Contract

The Markdown manuscript contract is convention-based, like the Markdown play contract, but maps Markdown elements to prose manuscript structure rather than acts, scenes, stage directions, characters, and dialogue.

Element schema:

- Front matter: H1 is the work title. H2-style metadata follows the existing script example convention where possible:

```markdown
# The Bus Stop

**A Short Play**

*by A. Playwright*

--- March 2026 ---
```

- Title: H1.
- Subtitle: standalone bold line immediately after title.
- Author: standalone italic line prefixed by the configured author attribution, default `by`.
- Date/version: existing `--- value ---` and `--- version | date ---` convention.
- Parts: H2 headings represent parts or major divisions.
- Chapters: H3 headings represent chapters.
- Sections: H4 and deeper headings represent local manuscript sections.
- Body text: plain paragraphs represent prose paragraphs.
- Scene breaks: a paragraph containing only `***` represents a manuscript scene break.
- Emphasis: Markdown emphasis and strong emphasis map to Typst emphasis and strong text.
- Code: inline backticks and fenced code blocks use `folio.manuscript.mono-font` and related mono settings.
- Footnotes: standard Markdown footnote references and definitions match the existing Markdown play contract.

### Org-mode Manuscript Contract

The org-mode manuscript contract should mirror the play org contract's use of front matter, headings, markup, footnotes, and `:noexport:`, but map headings to prose structure instead of stage-play structure. This contract must be documented with the same level of specificity as `docs/format-org.md`.

Basis from the current play org-mode contract:

- Play org front matter uses `#+KEY: value` lines and passes standard metadata through the event stream.
- Play org maps heading levels to structural roles.
- Play org uses inline markup in prose-bearing elements.
- Play org footnotes use `[fn:name]` references and standalone definitions.
- Play org excludes any heading tagged `:noexport:` and all of its children.

Manuscript org-mode keeps those conventions and changes only the semantic meaning of heading levels. It must not use the play parser's act, scene, stage-direction, character, and dialogue events for prose manuscript structure.

Element schema:

- Front matter: org keyword lines such as `#+TITLE:`, `#+SUBTITLE:`, `#+AUTHOR:`, `#+DATE:`, `#+VERSION:`, `#+WORDCOUNT:`, `#+ADDRESS:`, `#+EMAIL:`, and `#+WEBSITE:` provide manuscript metadata.
- Parts: level-1 headings represent parts or major divisions.
- Chapters: level-2 headings represent chapters.
- Sections: level-3 and deeper headings represent local manuscript sections.
- Body text: plain paragraphs under the current heading represent prose paragraphs.
- Scene breaks: a standalone org horizontal rule (`-----`) represents a manuscript scene break.
- Emphasis: org inline markup maps to Typst emphasis and strong text.
- Code: org inline code/verbatim and source blocks use `folio.manuscript.mono-font` and related mono settings.
- Footnotes: org footnote definitions and references match the existing org play contract.
- Private notes: any heading tagged `:noexport:` is excluded from output with all children.

Detailed org-mode mapping:

| Org syntax | Manuscript meaning | Rendering contract |
|---|---|---|
| `#+TITLE: About Time` | Manuscript title | Title-page title and running-header title source |
| `#+SUBTITLE: A Novel` | Manuscript subtitle | Title-page subtitle when present |
| `#+AUTHOR: Taḋg Paul` | Author full name | Title page and running-header author source |
| `#+DATE: July 2026` | Manuscript date | Title-page date when present |
| `#+VERSION: Draft 4` | Draft/version marker | Title-page version when present |
| `#+WORDCOUNT: 80000` | Approximate word count | Title-page word count when present |
| `#+ADDRESS: ...` | Postal address | Title-page contact block when present |
| `#+EMAIL: ...` | Email address | Title-page contact block when present |
| `#+WEBSITE: ...` | Website | Title-page contact block when present |
| `* PART ONE` | Part divider | Own page, centred vertically and horizontally |
| `** Chapter 1` | Chapter heading | New page, about one third down the page, body follows on same page |
| `*** The Station` | Section heading | Local manuscript section heading |
| Plain paragraphs | Body prose | Manuscript body paragraphs |
| `-----` | Scene break | Manuscript scene break |
| `/italic/`, `*bold*`, `_underline_` | Inline emphasis | Typst inline styling, consistent with org play markup handling |
| `~code~`, `=verbatim=`, source blocks | Monospace prose/code | Manuscript mono font settings |
| `[fn:name]` and `[fn:name] Text` | Footnote reference/definition | Typst footnote equivalent |
| Heading tagged `:noexport:` | Private note subtree | Excluded with all children |

Fountain is not accepted by manuscript mode. The manuscript contract is prose-oriented Markdown and org-mode only.

## Solution Design

### Language, frameworks, and libraries

- Keep the implementation in Perl, matching `bin/folio` and the `lib/Folio/*` modules.
- Reuse Typst for PDF compilation, matching existing PDF output.
- Reuse `Folio::Config` for layered configuration and dotted-path access.
- Use only core Perl modules unless a separate issue explicitly approves a new dependency.

### CLI shape

Add a new subcommand:

```text
folio manuscript <input>... <target> [options]
```

Inputs may be explicit files or quoted glob patterns. The command resolves all inputs, deduplicates exact paths, sorts deterministically by path, validates that every selected input is Markdown or every selected input is org-mode, and treats the final argument as the target when it has a supported output extension (`.pdf` or `.typ`).

When multiple input files are selected, the manuscript reader concatenates them with an inserted blank-line separator between each file before parsing or otherwise guarantees equivalent event separation. This prevents a file ending with `last line of prose.` and the next file beginning with `### Chapter 3` from becoming `last line of prose.### Chapter 3`.

Proposed options:

```text
  --title TITLE
  --subtitle SUBTITLE
  --author AUTHOR
  --author-attribution TEXT
  --date DATE
  --wordcount WORDS
  --version VERSION
  --style british|us
  --font FONT
  --font-size SIZE
  --heading-font FONT
  --heading-font-size SIZE
  --mono-font FONT
  --page SIZE
  --margin SIZE
  --line-spacing SIZE
  --paragraph-indent SIZE
  --paragraph-spacing SIZE
```

### Modules and patterns

- Add `Folio::Manuscript` as the orchestration layer for resolving input paths, loading chapter text, collecting metadata, and rendering.
- Add `Folio::Parser::ManuscriptMarkdown` and `Folio::Parser::ManuscriptOrg` or equivalent manuscript parser modules so prose structure does not overload the stage-play parsers.
- Add `Folio::Emitter::ManuscriptTypst` or an equivalent manuscript-specific Typst emitter so prose layout does not leak into `Folio::Emitter::Typst`, which is stage-play-specific.
- Keep reusable Typst compilation behaviour factored so stage-play, letter, and manuscript renderers can compile `.typ` to `.pdf` without duplicating subprocess handling.
- Extend `Folio::Config` with inherited lookup helpers for root, mode, and element-level values while preserving existing flat `folio.font` and `folio.letter.font` semantics.
- Migrate current stage-play rendering values into the new inheritance model without breaking existing `script.yaml` files.

### Anti-patterns to avoid

- Do not rename or replace existing root `folio.font`/`folio.font-size`; add heading defaults on top of the existing design.
- Do not require users to repeat root page/font choices under every mode.
- Do not reuse the stage-play event stream for prose-only manuscript layout where it would force artificial act, scene, character, or dialogue semantics.
- Do not add a word-processor or Pandoc dependency for rendering; existing PDF output is Typst-based.
- Do not parse structured configuration with regular expressions; follow CODING.md "Data Handling" and use the existing YAML parser path.
- Do not build shell commands as strings; follow CODING.md "Other Prohibited Shortcuts" and invoke external commands using argument arrays.
- Do not suppress Typst or filesystem errors; follow CODING.md "Error Suppression -- Forbidden Patterns".
